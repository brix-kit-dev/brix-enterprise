### 1.2 核心结论

**优势面（v1.1 改造已生效）**：
- ✅ R3 事件可观测性体系建成：`IntegrationEvent.traceId/tenantId @NonNull`、Kafka/InMemory/Webhook 三端 Micrometer 指标全覆盖（publish/consume/retry/DLQ）
- ✅ R4.2 契约一致性测试落地：`enterprise-host/host-contract-tests` 含 `EventBusContractTest`，验证 Standalone/Embedded 行为等价
- ✅ R6 Host 极薄度达标：`host-shell-standalone` 仅 2 个 Java 文件（启动类 + 空壳 AutoConfiguration）、零控制流、零 `@Bean`
- ✅ R7 前后端分离修复：`CaseDetailPageV2.tsx` 已切换到 `useCaseNodes` Hook，零 Repository 直引
- ✅ R12.3 安全加固：`TokenEncryptionConverter.DEFAULT_KEY` 已删除，未配置时抛出 `TokenEncryptionException`
- ✅ R16.12 多租户边界：`TenantFilter` 已支持 `tenantMode` 校验，多租户模式下 defaultTenantId 静默
- ✅ R16.1b 契约完整：`TenantCapability` 增补 `getCurrentRole/isActor/isSubject` 默认方法，`PasswordCapability` 移入 SDK
- ✅ R1 插件隔离零违规：12/12 插件 `*-core/pom.xml` 仅依赖 `runtime-sdk-api + {plugin}-api + JPA + Lombok`
- ✅ R15 BrixUI 治理零违规：12 个 `*-ui-web` 插件全部通过 `useUI()` 获取组件
- ✅ R16 多租户链路完整贯通：JWT(tid) → JwtTenantResolver → TenantResolverChain → TenantFilter → TenantContext → TenantInterceptor → 行级 SQL 隔离

**剩余阻塞面（v1.2 新发现）**：
- ❌ **品牌发布阻塞**：brix 仓库（开源代码库）残留 ~115 处 `shinwa/Shinwa` 旧品牌名，主要分布于：


### 3.5 【P0-5】schemaVersion 演进协议

**对应检查项**: R3.6
**严重等级**: High
**问题描述**: `IntegrationEvent.schemaVersion` 是 `int` 默认 1，无版本演进协议。一旦事件结构变更，消费端无法识别版本差异。

**涉及文件**:

| 文件路径 | 操作 |
|----------|------|
| `brix/packages/@brix/runtime-sdk/runtime-sdk-api/src/main/java/io/runtime/sdk/event/IntegrationEvent.java` | 增加 `MIN_SUPPORTED_SCHEMA_VERSION` 常量 + JavaDoc 协议 |
| `brix/packages/@brix/runtime-sdk/runtime-sdk-api/src/main/java/io/runtime/sdk/event/SchemaVersion.java` | 新建注解 `@SchemaVersion(value = 2, minCompatible = 1)` |
| 所有 `IntegrationEvent` 子类（含 enterprise-solutions/*-api/event/） | 标注 `@SchemaVersion` |

**协议规则**（写入 JavaDoc）:
1. **MAJOR (≥10)**：破坏性变更，消费端 schemaVersion < MAJOR 时拒绝处理
2. **MINOR (个位数)**：增量字段，消费端向后兼容
3. EventBus.publish 时校验 `event.schemaVersion >= MIN_SUPPORTED_SCHEMA_VERSION`

**验收标准**:
- [ ] IntegrationEvent JavaDoc 包含明确的 schemaVersion 演进协议
- [ ] 所有现有事件类标注 `@SchemaVersion(value = 1, minCompatible = 1)`
- [ ] 消费端 `EventBusCapability.subscribe()` 在版本不兼容时打 `log.warn` 并丢弃（不抛异常）

**影响功能**: ✅ 兼容向前（默认 schemaVersion=1）。

## 6. 链路完整性验证结果

### 6.1 多租户链路 ✅ 完整贯通

```
HTTP Request
  ↓ (X-Tenant-ID Header / JWT tenant_id claim)
JwtTenantResolver / HeaderTenantResolver
  ↓
TenantResolverChain  (优先级 + 冲突检测，冲突抛 TenantMismatchException → HTTP 403)
  ↓
TenantFilter         (设置 TenantContext ThreadLocal，校验 tenantMode)
  ↓
TenantInterceptor    (Hibernate filter 自动追加 tenant_id = ? 到所有 sys_*/biz_* 查询)
  ↓
TenantSqlGuardInterceptor (SQL 兜底校验，无 tenant_id 谓词的写操作抛 TenantSqlViolationException)
  ↓
DB
```

**残留风险**: 无（v1.1 P0-5 已修复 defaultTenantId 校验）。

### 6.2 事件链路 ✅ 完整贯通（含 traceId）

```
Plugin A: bookingService.publish(BookingCreatedEvent)
  ↓
EventBusCapability.publish()
  ↓ ensureTraceId() → MDC / OTel SpanContext / UUID fallback
  ↓ ensureTenantId() → TenantContext
  ↓ Micrometer counter("brix.event.published.total", "event=BookingCreatedEvent")
  ↓
[Kafka topic / In-memory queue / Webhook HTTP POST]
  ↓
Plugin B: @EventListener BookingCreatedEvent → handler
  ↓ Micrometer counter("brix.event.consumed.total")
  ↓ MDC.put("traceId", event.traceId)  (链路连续)
```

**残留风险**: schemaVersion 演进协议未定（P0-5 修复中）。

### 6.3 前端调用链 ✅ 严格分层

```
View (CaseDetailPageV2.tsx)
  ↓ 仅调用 Hook，零 fetch/axios
Hook (useCaseDetail / useCaseNodes)
  ↓ 通过 useCapability(HttpCapability)
Repository (createCaseRepository)
  ↓
HttpCapability (axios/fetch 实现，注入 traceId / tenant header)
  ↓
Backend REST Controller
```

**残留风险**: 无（v1.1 P0-6 已修复 CaseDetailPageV2）。

### 6.4 i18n 链路 ✅ 贯通（部分语言资源缺失）

```
locales/{zh-CN,en-US}.json
  ↓
I18nProvider (i18next + react-i18next)
  ↓
useTranslation() / t('key')
```

**残留风险**: ~30% 插件缺 `en-US.json`（P2-9 处理）。
