### 3.1 【P0-1】IntegrationEvent 增加 tenantId 字段

**对应检查项**: R3.6  
**严重等级**: High  
**问题描述**: `IntegrationEvent` 基类缺少 `@NonNull tenantId` 字段，跨插件事件消费端无法确认事件归属租户，可能导致跨租户数据处理。

**涉及文件**:

| 文件路径 | 操作 |
|----------|------|
| `brix/packages/@brix/runtime-sdk/runtime-sdk-api/src/main/java/io/runtime/sdk/event/IntegrationEvent.java` | 增加 `tenantId` 字段 |
| `brix/packages/@brix/infra-adapters/packages/server/infra-adapter-kafka/` | `publish()` 自动从 `TenantContext` 补全 tenantId |
| `brix/packages/@brix/infra-adapters/packages/server/infra-adapter-simple/` | 同上 |
| `brix-enterprise/packages/@brix/enterprise-solutions/shared-events/` | 现有事件类适配新基类 |

**具体修改方案**:

```java
// IntegrationEvent.java — 新增字段
public abstract class IntegrationEvent {
    
    // 现有字段
    private String eventId;
    private String sourceModule;
    private String correlationId;
    private String causationId;
    private int version;
    
    // ===== 新增 =====
    
    /**
     * Tenant ID this event belongs to.
     * Automatically populated from TenantContext if not explicitly set.
     * @since 3.2.0
     */
    @NonNull
    private String tenantId;
    
    /**
     * Schema version for consumer-side compatibility checking.
     * Consumers should skip events with unsupported schema versions.
     * @since 3.2.0
     */
    @NonNull
    private int schemaVersion = 1;
}
```

```java
// KafkaEventBusAdapter.java — publish() 自动补全
@Override
public void publish(IntegrationEvent event) {
    if (event.getTenantId() == null) {
        String tid = TenantContext.getCurrentTenantId();
        if (tid == null) {
            throw new IllegalArgumentException(
                "IntegrationEvent.tenantId is required. " +
                "Either set explicitly or ensure TenantContext is available."
            );
        }
        event.setTenantId(tid);
    }
    // 原有发布逻辑...
}
```

**注意事项**:
- ⚠️ 需升级 IntegrationEvent 版本号（建议 `schemaVersion` 从 1 开始）
- ⚠️ 消费端需兼容旧版事件（tenantId 为 null 时降级处理或拒绝）
- ⚠️ 前端 EventBus 同步增加 tenantId 字段

**验收标准**:
- [ ] IntegrationEvent 包含 `tenantId`（@NonNull）和 `schemaVersion` 字段
- [ ] EventBusCapability `publish()` 在 tenantId 缺失时从 TenantContext 自动补全
- [ ] tenantId 为 null 且 TenantContext 无值时 `publish()` 抛出 IllegalArgumentException
- [ ] 前端 EventBus emit 时自动注入 tenantId
- [ ] 现有 shared-events 中的事件可编译通过
- [ ] ArchitectureTest 增加 tenantId 完整性检查

**对应检查项**: R9.6

```yaml
# .github/workflows/api-compatibility.yml
name: API Compatibility Check
on:
  pull_request:
    paths:
      - '**/api/**'
      - '**/dto/**'
      - '**/controller/**'

jobs:
  openapi-diff:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Generate OpenAPI spec (current)
        run: mvn verify -pl host-shell-standalone -Popenapi-generate
      - name: Generate OpenAPI spec (base)
        run: |
          git checkout ${{ github.event.pull_request.base.sha }}
          mvn verify -pl host-shell-standalone -Popenapi-generate
      - name: Run OpenAPI diff
        uses: openapitools/openapi-diff-action@v1
        with:
          old-spec: target/openapi-base.json
          new-spec: target/openapi-current.json
          fail-on-breaking: true
```

**影响**: ❌ 不影响现有功能

### 4.4 【P1-4】增加 @ControllerAdvice 全局异常处理器

**对应检查项**: R10.3  
**当前状态**: 无显式全局异常处理器

**修改方案**:

在 `brix/packages/@brix/platform-commons/packages/server/platform-common-starter/` 中新增：

```java
@ControllerAdvice
@Order(Ordered.LOWEST_PRECEDENCE)
public class PlatformExceptionHandler {
    
    private static final Logger log = LoggerFactory.getLogger(PlatformExceptionHandler.class);
    
    @ExceptionHandler(MissingRequiredCapabilityException.class)
    public ResponseEntity<ProblemDetail> handleMissingCapability(
            MissingRequiredCapabilityException ex) {
        log.error("Missing required capability: {}", ex.getCapabilityName());
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(
            HttpStatus.SERVICE_UNAVAILABLE, ex.getMessage());
        problem.setTitle("Required Capability Unavailable");
        return ResponseEntity.status(503).body(problem);
    }
    
    @ExceptionHandler(TenantRequiredException.class)
    public ResponseEntity<ProblemDetail> handleTenantRequired(
            TenantRequiredException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(
            HttpStatus.FORBIDDEN, ex.getMessage());
        problem.setTitle("Tenant Context Required");
        return ResponseEntity.status(403).body(problem);
    }
    
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ProblemDetail> handleGeneral(Exception ex) {
        log.error("Unhandled exception", ex);
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(
            HttpStatus.INTERNAL_SERVER_ERROR, 
            "An unexpected error occurred");
        problem.setTitle("Internal Server Error");
        // 不暴露原始异常信息到响应体
        return ResponseEntity.status(500).body(problem);
    }
}
```

**影响**: ⚠️ 需确认不覆盖已有插件级异常处理

### 4.5 【P1-5】Retry/DLQ Micrometer 指标注册

**对应检查项**: R3.7  
**当前状态**: Kafka adapter 无 Retry/DLQ 的 Micrometer Counter

```java
// KafkaEventConsumer.java
private final MeterRegistry meterRegistry;

private void onConsumeSuccess(IntegrationEvent event) {
    meterRegistry.counter("brix.event.consumed.total",
        "eventType", event.getClass().getSimpleName(),
        "sourceModule", event.getSourceModule(),
        "tenantId", event.getTenantId()
    ).increment();
}

private void onConsumeRetry(IntegrationEvent event, int attempt) {
    meterRegistry.counter("brix.event.retry.count",
        "eventType", event.getClass().getSimpleName(),
        "attempt", String.valueOf(attempt)
    ).increment();
}

private void onConsumeDLQ(IntegrationEvent event, Throwable cause) {
    meterRegistry.counter("brix.event.dlq.count",
        "eventType", event.getClass().getSimpleName(),
        "sourceModule", event.getSourceModule(),
        "errorType", cause.getClass().getSimpleName()
    ).increment();
    log.error("Event sent to DLQ: eventId={}, type={}, cause={}",
        event.getEventId(), event.getClass().getSimpleName(), 
        cause.getMessage());
}
```

### 4.8 【P1-8】@CriticalEvent 注解与 Outbox 自动绑定

**对应检查项**: R13.4  
**当前状态**: 无 `@CriticalEvent` 标记机制

**修改方案**:

```java
// runtime-sdk-api — 新增注解
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface CriticalEvent {
    /**
     * Whether this event MUST go through Outbox pattern 
     * for guaranteed delivery.
     */
    boolean outbox() default true;
}
```

```java
// shared-events — 标记关键事件
@CriticalEvent
public class UserDisabledEvent extends IntegrationEvent { ... }

@CriticalEvent
public class TenantSuspendedEvent extends IntegrationEvent { ... }
```

```java
// infra-adapter-kafka — AOP 拦截
@Aspect
public class CriticalEventOutboxAspect {
    @Around("execution(* io.runtime.sdk.capability.EventBusCapability.publish(..))")
    public Object intercept(ProceedingJoinPoint pjp) {
        IntegrationEvent event = (IntegrationEvent) pjp.getArgs()[0];
        if (event.getClass().isAnnotationPresent(CriticalEvent.class)) {
            return outboxEventPublisher.publishViaOutbox(event);
        }
        return pjp.proceed();
    }
}
```

**影响**: ⚠️ 需增量上线，现有事件默认不标记 `@CriticalEvent`

## 9. 链路完整性验证结果

### 9.1 多租户链路 ✅ 贯通

```
JWT Token (tid claim)
  → JwtTenantResolver.java (解析 Authorization header)
    → TenantResolverChain.java (优先级排序 + 来源冲突检测)
      → TenantFilter.java (Servlet Filter, 设置 ThreadLocal)
        → TenantContext.setCurrentTenantId(tid)
          → TenantInterceptor.java (Hibernate StatementInspector)
            → SQL 自动注入 WHERE tenant_id = :tid
              → TenantSqlGuardInterceptor.java (开发环境漏检告警)
```

- Flyway V001-V006 建表：`sys_tenant`、`sys_identity`、`sys_tenant_member` + 业务表全部含 `tenant_id`
- 前端：`useTenant` hook → `TenantProvider` → Bearer Token 内嵌 tid

### 9.2 事件链路 ✅ 贯通

```
Plugin A (e.g. UserServiceImpl)
  → runtimeContext.getEventBus().publishIntegration(event)
    → IntegrationEvent { eventId, correlationId, causationId, sourceModule, version }
      → EventBusCapability adapter (Kafka / Simple)
        → EventRouter + EventLogger + EventLatencyTracker
          → Plugin B (消费端 subscriber)
```

- 前端 EventBus 同样支持 `emit()` / `on()` / `waitFor()` + BackpressureManager
- ⚠️ 缺少 `tenantId` 字段（Phase 1 修复）

### 9.3 前端调用链 ✅ 贯通

```
PartnerListPage.tsx (View 层)
  → usePartnerList() (Hook/ViewModel 层)
    → createPartnerRepository(http) (Repository 层, 工厂模式)
      → http.get('/v1/partners', params) (HttpCapabilityImpl)
        → fetch + interceptor chains + auth token injection
          → Backend PartnerController (@RestController)
```

- 12/12 插件遵循此链路
- 零 fetch 泄露到 View/Hook 层

### 9.4 i18n 链路 ✅ 贯通

```
Resource: zh-CN.ts (frame namespace, 40+ keys)
  → i18n.addResourceBundle({ locale, namespace, resources })
    → I18nCapabilityImpl → I18nStore (locale + namespace registry)
      → useI18n('partners') → { t, locale, setLocale }
        → t('partners:list.title') → 渲染翻译文本
```

- 支持运行时 locale 切换
- 插件级 namespace 隔离
