### 1.2 核心结论

**优势面（值得肯定）**：
- 12 个插件全部通过 R1（插件隔离）零违规
- 12/12 插件有 `ArchitectureTest.java`（ArchUnit 守护 8 条红线）
- Maven Enforcer `bannedDependencies` 已配置 12 项禁止依赖（含传递依赖检索）
- 前后端完全分离（R7）仅 1 处违规（CaseDetailPageV2），12 个插件严格遵循 View → Hook → Repository → HttpCapability 四层架构
- BrixUI 统一治理（R15）零违规，20+ 处 `useUI()` 使用，零 MUI/Antd 直接引用
- 租户链路（R16）核心路径贯通：JWT(tid) → TenantResolverChain → TenantFilter → TenantInterceptor(Hibernate) → 行级 SQL 隔离
- Transactional Outbox 模式完整：@CriticalEvent 注解 + CriticalEventOutboxAspect + event_outbox 表 + @Scheduled 处理器
- 安全体系扎实：RS256 非对称签名、BCrypt 密码加密、LogSanitizer 敏感信息掩码、mid/pid 互斥校验

**改进面（需要行动）**：
- **R3 事件可观测性系统性缺失**（本次评审发现的最严重问题）：
  - IntegrationEvent 缺少 `traceId` 字段（R3.1 — 仅有 correlationId/causationId）
  - 所有 EventBus 实现（Kafka/Simple/Webhook）缺少 Micrometer 指标埋点（R3.3/R3.7）
  - IntegrationEvent 的 `tenantId`/`schemaVersion` 未标 `@NonNull`（R3.6）
  - 前端 EventBus 仅 console.log，无 ObservabilityCapability 集成（R3.5）
- 硬编码加密密钥 `DEFAULT_KEY` 残留（R12.3 — TokenEncryptionConverter.java）
- TenantCapability 缺少 v1.2 方法（R16.1b — `isActor()`/`isSubject()`/`getCurrentRole()` 位于 `AuthenticatedUser` 而非契约接口）
- 默认租户无模式校验（R16.12 — 多租户模式下 defaultTenantId 仍可生效）
- CaseDetailPageV2.tsx 直接 import repository（R7.2 — 三层架构违反）
- 无 Standalone/Embedded 行为一致性 Contract Test（R4.2）
- Host 层存在历史遗留工具类（R6.2 — ExportKeys.java）
- switchTenant() 状态重置不完整（缺少 queryClient.clear()/resetState()）
- `@ComponentScan` 范围过广（扫描整个 `io.brix.platform`/`io.infra.adapter` 包树）
- 20+ 处 "Shinwa" 旧品牌名残留（开源阻塞）
- 47 个文件超 500 行（30 个 TSX + 17 个 TS）— 代码质量风险
- 版本号碎片化（1.0.0 / 3.0.0 / 3.1.0 / 3.3.0 / 3.4.0 混用）
- 测试覆盖度不足（Java 有 ArchUnit，TS 端测试稀疏）

### 3.1 【P0-1】IntegrationEvent 增加 traceId 字段

**对应检查项**: R3.1  
**严重等级**: Zero Tolerance  
**问题描述**: `IntegrationEvent` 仅有 `correlationId`/`causationId`，缺少 `traceId` 字段。蓝图明确要求事件必须包含 `traceId` 用于分布式追踪链路关联。

**涉及文件**:

| 文件路径 | 操作 |
|----------|------|
| `brix/packages/@brix/runtime-sdk/runtime-sdk-api/src/main/java/io/runtime/sdk/event/IntegrationEvent.java` | 增加 `traceId` 字段 |
| `brix/packages/@brix/infra-adapters/packages/server/infra-adapter-kafka/` | `publish()` 自动从 MDC/OpenTelemetry 注入 traceId |
| `brix/packages/@brix/infra-adapters/packages/server/infra-adapter-simple/` | 同上 |
| `brix/packages/@brix/runtime-sdk/runtime-sdk-api-web/src/types/event.ts` | TS 端同步增加 traceId 字段 |

**具体修改方案**:

```java
// IntegrationEvent.java — 新增字段
/**
 * Distributed trace ID for correlating events with OpenTelemetry traces.
 * Automatically populated from MDC/OTel context if not explicitly set.
 * @since 3.2.0
 */
@NonNull
private String traceId;
```

```java
// KafkaEventBusAdapter.java — publish() 自动补全
if (event.getTraceId() == null) {
    // 优先从 OpenTelemetry 获取，fallback 到 MDC
    Span currentSpan = Span.current();
    String trace = currentSpan.getSpanContext().getTraceId();
    if (TraceId.isValid(trace)) {
        event.setTraceId(trace);
    } else {
        String mdcTrace = MDC.get("traceId");
        event.setTraceId(mdcTrace != null ? mdcTrace : UUID.randomUUID().toString());
    }
}
```

**验收标准**:
- [ ] IntegrationEvent 包含 `traceId`（@NonNull）字段
- [ ] EventBus `publish()` 在 traceId 缺失时从 OTel/MDC 自动补全
- [ ] 前端 EventBus emit 时自动注入 traceId
- [ ] 消费端日志中可见 traceId，可关联分布式追踪

### 3.3 【P0-3】EventBus 全实现增加 Micrometer 指标

**对应检查项**: R3.3、R3.7  
**严重等级**: Zero Tolerance  
**问题描述**: 所有 EventBus 实现（KafkaEventBusCapability、InMemoryEventBusCapability、HttpWebhookEventBus）均无 Micrometer Counter/Timer 埋点，生产环境无法监控事件发布/消费/重试/DLQ。

**涉及文件**:

| 文件路径 | 操作 |
|----------|------|
| `brix/packages/@brix/infra-adapters/packages/server/infra-adapter-kafka-core/` | 注入 MeterRegistry，添加发布/消费指标 |
| `brix/packages/@brix/infra-adapters/packages/server/infra-adapter-kafka-outbox/` | 添加 Outbox 积压/处理/失败指标 |
| `brix/packages/@brix/infra-adapters/packages/server/infra-adapter-simple/` | 添加内存事件发布/消费指标 |

**具体修改方案**:

```java
// KafkaEventBusCapability.java
private final MeterRegistry meterRegistry;

@Override
public void publish(IntegrationEvent event) {
    Timer.Sample sample = Timer.start(meterRegistry);
    try {
        // 原有发布逻辑...
        meterRegistry.counter("brix.event.published.total",
            "eventType", event.getClass().getSimpleName(),
            "sourceModule", event.getSourceModule()
        ).increment();
        sample.stop(meterRegistry.timer("brix.event.publish.duration",
            "eventType", event.getClass().getSimpleName()));
    } catch (Exception e) {
        meterRegistry.counter("brix.event.publish.error",
            "eventType", event.getClass().getSimpleName(),
            "errorType", e.getClass().getSimpleName()
        ).increment();
        throw e;
    }
}

// 消费端指标
private void onConsumeSuccess(IntegrationEvent event) {
    meterRegistry.counter("brix.event.consumed.total",
        "eventType", event.getClass().getSimpleName(),
        "sourceModule", event.getSourceModule()
    ).increment();
}

private void onConsumeRetry(IntegrationEvent event, int attempt) {
    meterRegistry.counter("brix.event.retry.count",
        "eventType", event.getClass().getSimpleName(),
        "attempt", String.valueOf(attempt)
    ).increment();
}

private void onConsumeDLQ(IntegrationEvent event, Throwable cause) {
    meterRegistry.counter("brix.event.dlq.count",
        "eventType", event.getClass().getSimpleName(),
        "errorType", cause.getClass().getSimpleName()
    ).increment();
}
```

**影响**: ❌ 不影响现有功能（新增指标）

**验收标准**:
- [ ] Kafka/Simple/Webhook 三种实现均有 `brix.event.published.total`、`brix.event.consumed.total` Counter
- [ ] Kafka 实现有 `brix.event.retry.count`、`brix.event.dlq.count` Counter
- [ ] Kafka 实现有 `brix.event.publish.duration` Timer
- [ ] Actuator `/metrics` 端点可查询以上指标

**对应检查项**: R12.3  
**严重等级**: High  
**问题描述**: `TokenEncryptionConverter.java` 包含硬编码默认密钥 `DEFAULT_KEY = "brix-platform-token-encryption-key-change-in-production"`。虽有注释提示修改，但生产环境若未配置将使用默认值。

**涉及文件**:

| 文件路径 | 操作 |
|----------|------|
| `brix-enterprise/packages/@brix/enterprise-solutions/app-identity/identity-core/src/main/java/io/brix/enterprise/app/identity/entity/converter/TokenEncryptionConverter.java` | 移除 `DEFAULT_KEY`，改为配置注入 |

**具体修改方案**:

```java
// Before
private static final String DEFAULT_KEY = 
    "brix-platform-token-encryption-key-change-in-production";

// After — 从配置注入，缺失时启动失败
@Value("${brix.security.token-encryption-key}")
private String encryptionKey;

@PostConstruct
void validateKey() {
    if (encryptionKey == null || encryptionKey.isBlank()) {
        throw new IllegalStateException(
            "brix.security.token-encryption-key must be configured. " +
            "Generate a secure key using: openssl rand -base64 32"

    }
}
```

**注意事项**:
- ⚠️ 现有环境需在 `application.yml` 中配置 `brix.security.token-encryption-key`
- ⚠️ 已加密的 token 数据需使用原 key 解密后重新加密（或提供迁移工具）

**验收标准**:
- [ ] 代码中无硬编码密钥字符串
- [ ] 未配置密钥时应用启动失败并给出明确错误信息
- [ ] 现有加密数据可正常解密（配置原有密钥后）

**严重等级**: Zero Tolerance  
**问题描述**: `TenantFilter` 中 `defaultTenantId` 在多租户模式（`brix.tenant.mode=multi`）下仍可生效，导致未认证请求可能兜底到默认租户，破坏租户隔离边界。

```java
@Value("${brix.tenant.mode:single}")
private String tenantMode;

private String resolveDefaultTenant() {
    if ("multi".equals(tenantMode) && defaultTenantId != null) {
        log.warn("defaultTenantId is configured but tenant mode is 'multi'. " +
                 "Ignoring default tenant to prevent cross-tenant access.");
        return null;
    }
    return defaultTenantId;
}
```

**验收标准**:
- [ ] `brix.tenant.mode=multi` 时 `defaultTenantId` 不生效
- [ ] `brix.tenant.mode=single` 时行为不变

## 9. 链路完整性验证结果

### 9.1 多租户链路 ✅ 贯通

```
JWT Token (tid claim)
  → JwtTenantResolver.java (解析 Authorization header, @Order(0))
    → HeaderTenantResolver.java (@Order(100))
      → SubdomainTenantResolver.java (@Order(200))
        → PathTenantResolver.java (@Order(250))
          → TenantResolverChain.java (优先级排序 + 来源冲突检测)
            → TenantFilter.java (Servlet Filter, 设置 ThreadLocal, finally 中 clear())
              → TenantContext.setCurrentTenantId(tid)
                → TenantInterceptor.java (Hibernate StatementInspector)
                  → SQL 自动注入 WHERE tenant_id = :tid
                    → TenantSqlGuardInterceptor.java (开发环境漏检告警)
```

- Flyway V001-V012 建表完整：`sys_tenant`、`sys_identity`、`sys_tenant_member`、`sys_tenant_principal` + 业务表全部含 `tenant_id`
- TenantWhitelist: `sys_tenant`、`sys_identity`、`sys_tenant_member`、`sys_platform_admin`、`flyway_schema_history`
- 前端：`useTenant` hook → `TenantProvider` → `TenantSelector`/`TenantSwitcher` → Bearer Token 内嵌 tid
- ⚠️ 缺陷：switchTenant() 未调用 queryClient.clear()（Phase 2 修复）

### 9.2 事件链路 ⚠️ 部分贯通

```
Plugin A (e.g. UserServiceImpl)
  → runtimeContext.getEventBus().publishIntegration(event)
    → IntegrationEvent { eventId, correlationId, causationId, sourceModule, version, tenantId(@Since 3.2.0), schemaVersion(@Since 3.2.0) }
      → EventBusCapability adapter (Kafka / Simple / Webhook)
        → EventRouter + EventLogger + EventLatencyTracker
          → Plugin B (消费端 subscriber)
```

- Outbox 模式完整：@CriticalEvent → 同事务写 event_outbox → @Scheduled 发送（PENDING→PROCESSING→COMPLETED）
- 前端 EventBus 同样支持 `emit()` / `on()` / `waitFor()` + BackpressureManager
- ❌ 缺失：`traceId` 字段（Phase 1 修复）
- ❌ 缺失：Micrometer 指标（Phase 1 修复）
- ❌ 缺失：tenantId/schemaVersion 非 @NonNull（Phase 1 修复）

### 9.3 前端调用链 ✅ 贯通（1 处违规）

```
PartnerListPage.tsx (View 层)
  → usePartnerList() (Hook/ViewModel 层)
    → createPartnerRepository(http) (Repository 层, 工厂模式)
      → http.get('/v1/partners', params) (HttpCapabilityImpl)
        → fetch + interceptor chains + auth token injection
          → Backend PartnerController (@RestController)
```

- 12/12 插件遵循此链路
- ❌ 例外：CaseDetailPageV2.tsx 直接 import repository（Phase 1 修复）

### 9.4 认证链路 ✅ 贯通

```
JWT (RS256, classpath:keys/public.pem)
  → JwtValidator.java (验证签名 + mid/pid 互斥 + 过期时间)
    → AuthFilter.java (设置 SecurityContext)
      → AuthContextCapability (getCurrentUser/isAuthenticated)
        → 前端 useAuth() hook
```

- RS256 非对称签名确认
- mid/pid 互斥在 JwtValidator 中强制校验（同时存在则抛 JwtValidationException）
- Identity Token 限制 5 分钟 + allowed_actions
- JWT claims: tid, mid, pid, mtype, ptype, role, token_type, allowed_actions

### 9.5 i18n 链路 ✅ 贯通

```
Resource: zh-CN.ts (frame namespace, 40+ keys)
  → i18n.addResourceBundle({ locale, namespace, resources })
    → I18nCapabilityImpl → I18nStore (locale + namespace registry)
      → useI18n('partners') → { t, locale, setLocale }
        → t('partners:list.title') → 渲染翻译文本
```

- 支持运行时 locale 切换
- 插件级 namespace 隔离
- 12 个插件均有 `i18n/` 目录
