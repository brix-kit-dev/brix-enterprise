## 3. Layer 2A 契约清单（纯接口，长期稳定）

### 3.1 `UIAdapter` (41 个原子组件)

定义位置: `runtime-sdk-api-web/src/types/ui/adapter.ts`

| 类别 | 组件 |
|---|---|
| 布局 | `Box`、`Stack`、`Paper`、`Container`、`Divider` |
| 排版 | `Typography` |
| 数据展示 | `Table`、`Tag`、`List`、`Empty`、`Pagination`、`Avatar`、`Badge`、`Card` |
| 表单 | `Input`、`Select`、`Checkbox`、`Switch`、`Radio`、`Form` |
| 反馈 | `Alert`、`Spin`、`Progress`、`Modal`、`Tooltip`、`Popover`、`Popconfirm`、`Message` |
| 导航 | `Menu`、`Tabs`、`Breadcrumb`、`Steps`、`Drawer`、`Collapse` |
| 基础 | `Button`、`Icon` |

> **禁止纳入**: `Sidebar` / `Header` / `Layout` — 这些是 Shell 层职责。

### 3.2 `DesignTokens` (Brix 语义, 非 MUI 语义)

定义位置: `runtime-sdk-api-web/src/types/ui/design-tokens.ts`

```text
DesignTokens
├─ colors
│   ├─ brand        (primary/primaryLight/primaryDark/primaryContrast/secondary*)
│   ├─ surface      (page/card/raised/sunken/overlay)
│   ├─ text         (primary/secondary/disabled/inverse)
│   ├─ border       (default/strong/subtle/focus)
│   ├─ status       (success/warning/error/info + Light 变体)
│   └─ layout       (sidebar/header/divider)
├─ typography       (displayLarge … bodySmall … labelSmall)
├─ space            (xs / sm / md / lg / xl / xxl)
├─ spacing(n)       (函数, 8px 基数)
├─ shape            (sm/md/lg/full, string 类型如 '8px')
├─ shadows          (none/sm/md/lg/xl)
├─ breakpoints      (xs/sm/md/lg/xl)
├─ motion           (duration + easing)
└─ zIndex          (drawer/modal/popover/tooltip)
```

### 3.3 `ThemeCapability`

定义位置: `runtime-sdk-api-web/src/types/theme.ts`

interface ThemeCapability {
  getDesignTokens(): DesignTokens;   // ⭐ 插件唯一入口
  getMode(): 'light' | 'dark';

  // ... event subscriptions
}

## 4. 三层设计令牌体系（关键概念，记住它）

```text
Layer 1: Primitive Tokens (静态原语)
  📦 @brix-sdk/platform-design-tokens
  • 静态常量, 不响应暗色模式
  • 仅 platform-frame-web / infra-adapter-ui-* 可消费
  • ESLint: no-direct-design-tokens-import 禁止插件直接 import

Layer 2: Semantic Tokens (运行时语义)
  📦 runtime-sdk-api-web → DesignTokens 接口
  📦 platform-frame-web → ThemeCapabilityImpl 实现
  📦 infra-adapter-ui-{mui,native} → DesignTokenResolver 实现
  • 响应暗色/亮色 + 租户品牌
  • 插件唯一通过 useTheme().tokens 消费

Layer 3: Component Tokens (业务语义)
  📦 各插件 theme/ 目录
  • 仅允许业务领域语义色 (PARTNER_TYPE_COLORS, CASE_STATUS_COLORS)
  • 必须引用 Layer 2 (例: statusConfig.dot = tokens.colors.status.error)
  • ESLint: no-plugin-theme-tokens 禁止重定义平台令牌结构
```

## 6. 插件开发模板（写一个新插件就照抄）

```typescript
// app-foo/foo-ui-web/src/views/FooPage.tsx
import { useUI, useTheme } from '@brix-sdk/runtime-sdk-react';
import { FOO_STATUS_COLORS } from '../theme/fooBusinessColors';  // 仅业务语义色

export const FooPage = () => {
  const ui = useUI();              // ✅ 取 UI 组件
  const { tokens, isDark } = useTheme();   // ✅ 取设计令牌

  return (
    <ui.Card sx={{ padding: tokens.space.md, borderRadius: tokens.shape.md }}>
      <ui.Typography variant="titleMedium" color={tokens.colors.text.primary}>
        Hello
      </ui.Typography>
      <ui.Tag color={FOO_STATUS_COLORS.ACTIVE}>状态</ui.Tag>
    </ui.Card>
  );
};
```

**插件 package.json 必须**:
```json
{
  "peerDependencies": {
    "@brix-sdk/shared-runtime-web": "^3.2.0",
    "@brix-sdk/runtime-sdk-api-web": "^3.2.0",
    "@brix-sdk/runtime-sdk-react": "^3.2.0",
    "react": "^18.3.1",
    "react-dom": "^18.3.1",
    "react-router-dom": "^6.30.1"
  },
  "devDependencies": {
    "@brix-sdk/shared-runtime-web": "link:../../../../../../brix/packages/@brix/shared-runtime/shared-runtime-web",
    "@brix-sdk/runtime-sdk-api-web": "link:../../../../../../brix/packages/@brix/runtime-sdk/runtime-sdk-api-web",
    "@brix-sdk/runtime-sdk-react": "link:../../../../../../brix/packages/@brix/runtime-sdk/runtime-sdk-react"
  }
}
```

**禁止出现**: `@mui/material`、`@brix-sdk/platform-design-tokens`、`@emotion/*`。

## 8. 可观测事件日志字段集

后端 IntegrationEvent 发布/消费日志必须使用统一字段名，便于 ELK / OpenTelemetry 日志聚合与跨租户排障。

| 字段 | 含义 | 来源 |
|---|---|---|
| `name` | 事件名称 / 事件类型 | `IntegrationEvent.name()` |
| `sourcePlugin` | 事件来源插件或平台模块 | `IntegrationEvent.sourcePlugin()` |
| `tenantId` | 租户标识 | `IntegrationEvent.tenantId()` |
| `traceId` | 请求链路标识 | `IntegrationEvent.traceId()` / MDC `traceId` |
| `eventId` | 事件唯一标识 | `IntegrationEvent.eventId()` |

日志模板固定为：

```text
event.published name={} sourcePlugin={} tenantId={} traceId={} eventId={}
event.consumed name={} sourcePlugin={} tenantId={} traceId={} eventId={}
```

## 9. 文档治理约定

1. **本文件就是入口**。`docs-dev/` 任何新文档必须在本文 §0 阅读指引中加链接，否则会被视为孤儿文档。
2. **新设计先改蓝图**。任何架构变更必须先修改 `docs/v3.0.9-…蓝图.md`，再回写本文 §1~§5。
3. **改造计划用一次扔一次**。新的 `XXX改造计划-vN.md` 完成落地后立即移入 `archived/`，不留并行版本。
4. **不为「已完成的事」建文档**。如本文 §7 矩阵中所有项 ✅，则不再有独立的"改造计划"文档存在的必要。
5. **代码与文档同步证明**。本文每次更新需在文件头 `日期` 字段更新到该次 PR 日期，并在 §7 矩阵补一行验证。
