## 0. TL;DR

当前前端**架构骨架是合规的**（分层清晰、能力契约严、MF 单实例），但缺 4 类"系统级安全网"，导致测试时频繁碰到不稳定现象：

| 缺口 | 现象 | 改造编号 |
|---|---|---|
| 无统一 ErrorBoundary / Suspense Fallback | Remote 加载失败整页白屏 | C-1 |
| HTTP 错误未全局收敛 | 按钮点了"没反应" | C-2 |
| 无 PageState / SubmitGuard 公约 | 重复提交、Loading 闪烁 | C-3 |
| 超管视角（ViewMode）未显式建模 | 越权风险、菜单错乱 | C-4 |
| 超管路径零自动化测试 + CI 未卡 lint | 回归无感知 | C-5 / C-6 |

按 4 个 Phase 实施，每个 Phase 独立可发布、独立可回滚。

---

## 1. 改造原则（红线，先于任何代码动作）

| # | 原则 | 反模式 |
|---|---|---|
| R-1 | 所有新能力先定 **Layer 2A 契约**，再在 **Layer 2C** 实现 | 直接在插件 / Host 写实现 |
| R-2 | Host 仍然 **极薄**：只组装、零业务、零工具 | 在 host-shell-* 写 ErrorBoundary 代码 |
| R-3 | 插件 **0 行**直接 import `@mui/material` / `@brix-sdk/platform-design-tokens` / `localStorage` / `fetch` | 任何"临时方便" |
| R-4 | 视角切换（PlatformAdmin ⇄ TenantActor ⇄ TenantSubject）**必须后端重签 JWT**，前端只持 token | 纯前端 setTenantId 后并行调接口 |
| R-5 | 任何新增 Capability 必须配套 **ESLint 规则 + 单测** | "先用着，规则后补" |
| R-6 | **不破坏现有契约签名**，只做加法（向后兼容） | 改 `UIAdapter` 现有 41 个组件 props |
| R-7 | **不引入新依赖**（除 testing 必需的 `@testing-library/react` / `@playwright/test`） | 装新 UI 库 / 状态库 |

> **冲突处理**：若实施过程中发现某项必须破坏 R-1~R-7 才能完成，**停止编码，先改本文档并通过评审**。

## 2. 总体路线图

```
Phase 1  系统级安全网（解眼前痛点）          —— 让 UI 不再"莫名失败"
   ├─ C-1  ErrorBoundary + RemoteLoader Capability
   ├─ C-2  HTTP 全局错误总线
   └─ C-3  usePageState / useSubmitGuard / useConfirm

Phase 2  超管视角显式化（解越权与菜单错乱）   —— 让超管功能可信
   └─ C-4  ViewModeCapability + 菜单 requiredViewMode + RequireRole 守卫

Phase 3  防回归底座                             —— 让超管可测、可发布
   ├─ C-5  超管最小测试套件（unit + e2e）
   └─ C-6  CI architecture-check 卡点

Phase 4  体验一致性增强（合规与打磨）          —— 大厂级 polish
   ├─ C-7  Skeleton / Empty / Error 三态统一
   ├─ C-8  表单规范（Form.useForm 收敛）
   └─ C-9  a11y 基线（aria + 键盘导航）
```

每个 Phase **独立 PR、独立可发布**。Phase N+1 不依赖 Phase N 的业务结果，仅依赖契约。

## 3. Phase 1 — 系统级安全网

### 3.1 C-1：ErrorBoundary + RemoteLoader Capability

#### 问题
- Remote 模块加载失败、运行时抛错 → 整页白屏；
- Host 中 `routes.config.tsx` 直接用 `lazy()`，无 fallback、无 retry。

#### 设计
| 层 | 文件（新增/修改） | 内容 |
|---|---|---|
| 2A 契约 | `runtime-sdk-api-web/src/types/ui/error-boundary.ts` 新增 | `ErrorBoundaryProps { fallback: ReactNode; onError?(err, info) }` |
| 2A 契约 | `runtime-sdk-api-web/src/types/ui/adapter.ts` 修改 | `UIAdapter` 新增第 42 个组件 `ErrorBoundary` |
| 2A 契约 | `runtime-sdk-api-web/src/types/mf/remote-loader.ts` 新增 | `RemoteLoaderProps { name; module; fallback; errorFallback; retry? }` |
| 2C 实现 | `infra-adapter-ui-mui/src/components/ErrorBoundary.tsx` | React 16 ErrorBoundary class 实现 |
| 2C 实现 | `infra-adapter-ui-native/src/components/ErrorBoundary.tsx` | 同上（无样式依赖） |
| 2C 实现 | `infra-adapter-mf-web/src/components/RemoteComponent.tsx` 新增 | `<Suspense><ErrorBoundary>{lazy()}</ErrorBoundary></Suspense>` 三明治 |
| Host | `host-shell-standalone-web/src/config/routes.config.tsx` 修改 | 用 `<RemoteComponent>` 替换裸 `lazy()`；**仅替换调用，不写实现** |

#### 验收标准
- [ ] 故意把 `app-tenant` remoteEntry 改坏 → 页面只在该路由区域显示"加载失败 + 重试"，其余菜单/Header 正常；
- [ ] 抛 runtime error → 同样区域降级，控制台能看到 `onError` 上报；
- [ ] `pnpm lint` 仍然 0 violations；
- [ ] Host 改动 < 30 行，且只是组件名替换。

#### 红线检查
- ❌ Host 不能 import `react-error-boundary` 或写任何 try/catch；
- ✅ ErrorBoundary 必须通过 `useUI().ErrorBoundary` 暴露给插件复用。

---

### 3.2 C-2：HTTP 全局错误总线

#### 问题
- `infra-adapter-http-web` 只处理 401，403/409/422/5xx/network 全部静默；
- 用户感知"按钮点了没反应"。

#### 设计
| 层 | 文件 | 内容 |
|---|---|---|
| 2A 契约 | `runtime-sdk-api-web/src/types/events/system-events.ts` 新增 | `SystemHttpErrorEvent { status; code; message; traceId; url; method }` |
| 2C 实现 | `infra-adapter-http-web/src/interceptors/error.ts` 修改 | 4xx/5xx/network → `eventBus.publish('system.http.error', evt)` |
| 2C 实现 | `platform-frame-web/src/HttpErrorToaster.tsx` 新增 | 订阅事件 → `useUI().message.error`；带去重 5s 窗口 |
| Host | `host-shell-standalone-web/src/App.tsx` 修改 | 挂载 `<HttpErrorToaster/>`（一行） |

#### 错误分级映射
| status | 行为 |
|---|---|
| 401 | 跳登录（已实现，保留） |
| 403 | message.error('无权限')，**不跳转** |
| 409 / 422 | message.warning，业务层可拦截事件自定义处理 |
| 5xx / network | message.error('服务暂不可用，请稍后重试')，附 traceId |

#### 验收标准
- [ ] 后端故意返回 500 → 顶部 Toast 显示"服务暂不可用 traceId=xxx"；
- [ ] 同一接口连续 500 三次 → 只弹一次（5s 去重窗口）；
- [ ] 业务页面可通过 `useEventBus().subscribe('system.http.error', ...)` 拦截特定 url 自定义处理。

### 3.3 C-3：usePageState / useSubmitGuard / useConfirm

#### 问题
- 各插件手写 `loading/error/empty` 三态，不统一；
- Modal 提交按钮无防重，导致重复创建。

#### 设计
| 层 | 文件 | 内容 |
|---|---|---|
| 2B 共享 | `runtime-sdk-react/src/hooks/usePageState.ts` 新增 | 输入 `{loading, error, data}` → 输出 `{state: 'loading'\|'empty'\|'error'\|'success', render(node)}` |
| 2B 共享 | `runtime-sdk-react/src/hooks/useSubmitGuard.ts` 新增 | 包装异步函数，提交期间返回 `disabled=true`，失败自动解锁 |
| 2B 共享 | `runtime-sdk-react/src/hooks/useConfirm.ts` 新增 | 基于 `useUI().Modal.confirm`，标准化危险操作二次确认 |

> **不引入实现依赖**：三个 hook 内部只组合 `useUI()` / `useEventBus()`。

#### 验收标准
- [ ] app-tenant `TenantList` 改用 `usePageState`，行数减少 ≥ 20%；
- [ ] `TenantCreate` 提交按钮在请求中 disabled，连点 5 次只发 1 次请求；
- [ ] 删除租户走 `useConfirm`，UI 文案统一。

## 4. Phase 2 — 超管视角显式化（C-4）

### 4.1 问题
- 当前超管"切换租户"靠前端往 `TenantCapability.setTenantId()` 写值，**没有显式视角概念**；
- 菜单不按视角过滤，CUSTOMER 也能看到"租户管理"菜单（点了被 403 拒绝，UX 像 Bug）；
- 违反 B2B2C §2.3 **JWT mid/pid 互斥规则**——前端不能任意切换。

### 4.2 设计
| 层 | 文件 | 内容 |
|---|---|---|
| 2A 契约（后端） | `runtime-sdk-api/.../capability/ViewModeCapability.java` 新增 | `enum ViewMode { PLATFORM_ADMIN, TENANT_ACTOR, TENANT_SUBJECT }`；`getCurrent()`, `switch(mode, tenantId)` |
| 2A 契约（前端） | `runtime-sdk-api-web/src/types/view-mode.ts` 新增 | 同上 TS 镜像 |
| 2C 实现 | `platform-tenant/.../ViewModeCapabilityImpl.java` 新增 | 视角切换 → 重签 JWT（mid 或 pid 互斥） |
| 2C 实现 | `platform-tenant-web/src/hooks/useViewMode.ts` 新增 | `const { mode, switchTo } = useViewMode()` |
| 2C 实现 | `platform-tenant-web/src/components/PlatformAdminBanner.tsx` 新增 | 顶部红条："您正在以平台超管身份操作 [退出超管视角]" |
| 2C 实现 | `platform-tenant-web/src/components/RequireViewMode.tsx` 新增 | 路由守卫；不匹配 → 跳 403 页 |
| Plugin manifest | `enterprise-solutions/app-*/manifest.json` | 菜单项新增 `requiredViewMode: ['PLATFORM_ADMIN']` |
| Host | `routes.config.tsx` 修改 | 平台管理路由包 `<RequireViewMode mode="PLATFORM_ADMIN">` |

### 4.3 视角切换流程（必须后端重签）
```
前端点击"以租户 X 身份查看"
  → POST /api/auth/view-mode/switch  { mode: TENANT_ACTOR, tenantId: X }
  → 后端校验 JWT.role=PLATFORM_ADMIN
  → 后端签发新 JWT { sub, tid=X, mid=null, pid=null, role=PLATFORM_ADMIN_VIEWING, originalSub }
  → 前端替换 token，整页 reload（最简单可靠）
  → 顶部红条"超管模式 — 当前查看 tenant=X [返回平台]"
```

### 4.4 验收标准
- [ ] CUSTOMER 登录后看不到"租户管理 / 平台超管"菜单项；
- [ ] PLATFORM_ADMIN 切到 TENANT_ACTOR 视角后，URL 守卫拦截访问 `/admin/*`；
- [ ] 顶部红条始终可见；点"退出超管视角"恢复原 token；
- [ ] 后端日志可审计：`audit_log` 中每次 viewMode 切换都有记录（含 originalSub）。

### 4.5 红线
- ❌ 前端不能直接读 `JWT.payload` 判断角色，必须 `useViewMode()`；
- ❌ 不允许有"前端持有 platformAdminToken + tenantToken 双 token"方案；
- ❌ 视角切换不允许走 SPA 内路由 push，**必须 reload** —— 否则旧 RuntimeContext 会泄漏。

## 11. 附录 B — Phase 1 第一周可立即开工的具体任务

> 给"想马上开始"的开发者，列出 Phase 1 不需要等任何前置的可并行任务：

1. **任务 1**（独立）：在 `runtime-sdk-api-web` 新建 `error-boundary.ts` + `remote-loader.ts` 契约接口。
2. **任务 2**（独立，依赖 1）：`infra-adapter-ui-mui` / `infra-adapter-ui-native` 各实现一个 `ErrorBoundary`。
3. **任务 3**（独立，依赖 1 + 2）：`infra-adapter-mf-web` 新增 `RemoteComponent`。
4. **任务 4**（独立）：`runtime-sdk-react` 新增三个 hook（usePageState / useSubmitGuard / useConfirm）。
5. **任务 5**（独立）：`runtime-sdk-api-web/types/events/system-events.ts` 新增 `SystemHttpErrorEvent`。
6. **任务 6**（依赖 5）：`infra-adapter-http-web` 错误拦截器接入 EventBus。
7. **任务 7**（依赖 5）：新建 `HttpErrorToaster` 组件并在 Host 挂载。
