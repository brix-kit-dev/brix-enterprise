## 一、v2.1 架构端口规划总览

> **v2.1 关键变更**：插件（Plugin）不再独立运行，由服务（Service）组装后运行。
> 因此后端端口改为按**服务**分配，而非按插件分配。

| 端口段 | 用途 | 说明 |
|--------|------|------|
| **3000-3099** | Web 前端开发 | 基座 + 插件 Web 前端本地开发 |
| **4000-4099** | Mobile 前端开发 | 基座 + 插件 Mobile 前端本地开发 |
| **4317-4318** | 可观测性服务 | OpenTelemetry gRPC/HTTP |
| **5432-5499** | 数据库服务 | PostgreSQL（按服务分配） |
| **6379-6399** | 缓存服务 | Redis（按服务分配） |
| **8080-8089** | 基座后端服务 | Gateway、Auth Center |
| **8081-8089** | 服务后端（核心） | shinwa-service-platform/case/medical |
| **8100-8199** | 服务后端（扩展） | 未来业务服务 |
| **9000-9099** | 对象存储/管理控制台 | MinIO、Kafka |

## 九、新服务接入端口分配流程（v2.1）

### 9.1 v2.1 架构说明

> **重要**：v2.1 架构中，插件（Plugin）不再独立运行。
> 新增业务能力时，有两种方式：
> 1. **新增插件** → 作为 JAR 包被现有服务组装
> 2. **新增服务** → 组装多个插件后独立运行

### 9.2 新增服务端口分配

当需要添加新的业务服务时，请按以下步骤分配端口：

```yaml
# 示例: shinwa-service-analytics 数据分析服务

后端服务:
  shinwa-service-analytics: 8100

数据库:
  postgres: 5440
  redis: 6390

前端（如需）:
  analytics-web: 3051
  analytics-mobile: 4051
```

### 9.3 新增插件前端端口分配

插件虽然后端不独立运行，但前端模块仍需开发端口：

```yaml
# 示例: plugin-report 报表插件

前端服务:
  plugin-report-web: 3052
  plugin-report-mobile: 4052

# 后端由 shinwa-service-analytics 组装，无需独立端口
```

### 9.4 更新配置

1. 更新服务 `docker-compose.yml` 端口映射
2. 更新服务 `application.yml` 服务端口
3. 更新前端 `rspack.config.ts` 开发端口
4. 更新本文档的端口分配记录

## 十、注意事项

### 10.1 v2.1 架构关键变更

| 项目 | v1.x（旧） | v2.1（新） |
|------|-----------|-----------|
| 插件后端 | 独立运行，每个插件一个端口 | 不独立运行，由服务组装 |
| 服务后端 | 无 | 组装插件后运行，每个服务一个端口 |
| 数据库 | 每个插件一个数据库 | 每个服务一个数据库 |
| 前端 | 每个插件可有 web/mobile | 保持不变 |

### 10.2 端口冲突避免

- **React Native Metro Bundler** 默认使用 `8081`，与 shinwa-service-platform 端口相同
- **v2.2 解决方案**：Mobile 端口调整为 `4000`，避免冲突
- 启动命令：`npx react-native start --port 4000`

### 10.3 Docker 网络规划

- 所有服务通过 `shinwa-network` 网络互联
- 各服务使用独立的 PostgreSQL 和 Redis 实例
- Kafka 和 MinIO 由所有服务共享

### 10.4 移动端开发网络配置

Android 模拟器访问 Docker 容器服务需要特殊配置：

#### ⚠️ 重要说明

- `10.0.2.2` 是 Android 模拟器访问宿主机的特殊 IP
- **但是**：如果后端服务运行在 Docker 容器中，`10.0.2.2` 可能无法正确路由到容器
- **解决方案**：使用宿主机的**实际局域网 IP 地址**

#### 配置步骤

1. **获取宿主机 IP 地址**
   ```powershell
   # Windows
   ipconfig | Select-String "IPv4"
   # 查找类似 192.168.x.x 或 10.x.x.x 的地址
   ```

2. **更新 `.env` 配置**（platform-host-mobile）
   ```dotenv
   # 开发主机 IP（替换为您的实际 IP）
   DEV_HOST_IP=192.168.1.100
   
   # API 基础 URL（通过 Gateway 访问）
   API_BASE_URL=http://192.168.1.100:8900
   ```

3. **确保 Docker 端口正确暴露**
   ```yaml
   # docker-compose.yml 中的 Gateway 配置
   gateway:
     ports:
       - "8900:8900"  # 绑定到所有接口
   ```

### 10.5 生产环境建议

- 生产环境建议使用 Kubernetes Service 或服务网格，而非固定端口
- 本端口规划主要用于**本地开发**和 **Docker Compose** 部署
- 生产环境通过环境变量 `${SERVICE_PORT}` 动态配置
