### 2.1 Page → Hook/ViewModel → Repository → Capability

```text
Page / View / Component
        ↓
Hook / ViewModel
        ↓
Repository
        ↓
HttpCapability / generated Query client
```

[BRX-FE-LAYER-001] Page/View 只负责渲染和用户事件绑定，不得调用 `fetch`、`axios`、拼接 URL、直接导入 Repository、解析 JWT 或读取原始 Token。

[BRX-FE-LAYER-002] Hook/ViewModel 负责加载、刷新、分页、请求取消、交互编排、表单提交、稳定错误呈现和重复提交阻断。Hook 不得构造 URL、访问浏览器全局凭证或绕过 Repository。

[BRX-FE-LAYER-003] Repository 负责生成 DTO、请求/响应 Schema、稳定错误映射、缓存边界和取消语义。Repository 只能经 Runtime 注入的 `HttpCapability` 或生成的 typed Query client 访问后端，不得依赖 `fetch`、`axios` 或传输实现。

[BRX-FE-LAYER-004] Http/Query Capability 负责认证请求桥、Trace、deadline、取消、重试预算和统一错误边界。业务前端不得取得裸 bearer/refresh token。

依赖只允许 `Page → Hook → Repository → Capability Contract`。反向依赖、Page 直连 Repository、跨插件导入 Repository 或共享可变业务状态均为构建阻断项。

### 2.2 Shared Runtime 与 Module Federation

[BRX-FE-RUNTIME-001] 每个 UI Host 只能存在一个平台定义的 React realm、Router、Auth、Theme、I18n、State 和 UI Contract。官方插件及同 JS 权限域第三方插件必须从 `@brix-sdk/shared-runtime-*` 获取这些能力。

[BRX-FE-RUNTIME-002] React、ReactDOM、Router 和平台关键运行时由前端 BOM 生成精确兼容范围并由 Host 提供。插件使用 peer dependency，不得打包第二份运行时。

[BRX-FE-RUNTIME-003] 同一发布列车且没有独立部署要求时优先构建期组合。Module Federation 只用于确有独立部署要求的 Web Profile，并必须满足：

1. React、ReactDOM、Router 为 `singleton: true`、`strictVersion: true`；
2. 固定 `shareScope="default"`；
3. `requiredVersion` 由前端 BOM 生成；
4. Remote 使用 `import: false`；
5. Host/Remote 均不得使用 `eager: true`；
6. CI 校验构建产物、Federation manifest 和运行时实例身份；
7. 普通库不得无差别配置为 singleton。

[BRX-FE-RUNTIME-004] Module Federation 不是安全隔离。不可信 UI 必须部署到独立 origin，通过 sandboxed iframe 和版本化 message bridge 交互。

### 2.3 Route、Guard 与身份上下文

[BRX-FE-ROUTE-001] 路由必须来自已校验的 UI Manifest 或 Host Composition。业务代码不得拼装未知远程入口；无实现、权限或 Host 能力时必须隐藏入口，不得加载空壳页面。

[BRX-FE-ROUTE-002] Route Guard 只依据 Auth Capability 返回的已验证 scope、permissions 和 session state 判定。Guard 不得解析 JWT、仅依赖角色字符串或把前端隐藏当成后端授权。

[BRX-FE-ROUTE-003] Platform、Actor、Subject 和 Bootstrap Setup 上下文必须隔离：

- Platform Token 只进入 `/platform/**` 正式控制面；
- Actor Token 只进入租户管理和业务上下文；
- Subject Token 不得进入 Actor 管理路由；
- `BOOTSTRAP_SETUP` 只进入显式 bootstrap/setup 路由；
- 上下文切换必须清空查询缓存、业务状态和旧路由准入；
- 浏览器端的 Platform、Actor、Subject 会话均经 BFF；控制台只消费 BFF 会话状态，不处理凭证，也不持有 Token（v1.2）。

[BRX-FE-ROUTE-004] setup、reset、invite 页面属于身份协议面的托管页面（v1.2），必须设置 `Referrer-Policy: no-referrer`。安全 Token 仅存在于完成流程所需的最短内存生命周期，不得进入查询串、localStorage、sessionStorage、日志、遥测、错误消息或持久化状态。

### 2.3a 会话、托管登录与再验证（v1.2）

[BRX-FE-AUTH-002] AuthCapability 的会话状态（身份、上下文、权限、`acr`、过期时间）只来自 BFF 会话接口，不来自 Token；前端 MUST NOT 持有 Access/Refresh Token（根 S-20）。

[BRX-FE-AUTH-003] HttpCapability 对同源 API 使用会话 Cookie 与 CSRF 自定义请求头。收到 `auth.step_up_required` 或会话过期时，统一经身份协议面重新认证，完成后返回原页面；页面与 Hook 不得自行处理认证跳转。

[BRX-FE-AUTH-004] 托管登录页属于身份协议面的 UI 模块（platform-commons 下独立模块，由身份协议面在 `/auth/**` 下提供），遵守 BrixUI、i18n 与页面状态规则；另外 MUST 禁止第三方脚本，并使用严格 CSP 与 `frame-ancestors 'none'`。

[BRX-FE-AUTH-005] 业务前端与控制台 MUST NOT 提供密码、TOTP、passkey、恢复码等凭证输入页面（根 `BRX-RS-UI-018`）；未登录时由 BFF 跳转托管登录，控制台之间不互相链接或自动跳转登录入口（身份认证专项 BRX-IA-FLOW-005）。

### 2.4 页面生产级最小状态

[BRX-FE-UX-001] 每个用户可见异步页面必须显式处理首次加载、后台刷新、可重试错误、不可重试/权限错误、空状态、成功状态、请求取消、卸载和重复提交阻断。

[BRX-FE-UX-002] 表单由 Hook/ViewModel 编排 Schema 校验、字段错误、服务端稳定错误映射和提交状态；Page 不得以临时布尔值绕过校验或权限。

[BRX-FE-UX-003] 错误提示不得暴露原始堆栈、内部类名、Token、完整安全 URL、PII 或 Provider 原始消息。未知错误映射为平台安全错误并保留 traceId。

[BRX-FE-UX-004] Message、Alert、Modal、Empty、Spin 和 Form 等反馈组件全部通过 BrixUI/useUI 使用，不得调用第三方 UI 全局 API。

### 2.5 UI Manifest、契约与制品

[BRX-FE-CONTRACT-001] 前后端只共享版本化 Schema 及生成 DTO，不共享跨语言运行时代码。Repository 必须消费生成类型。

[BRX-FE-CONTRACT-002] UI Manifest 必须声明 module identity、Runtime/BOM 范围、routes、permissions、shared runtime 和专业组件逃生舱。Manifest 与实际导出、路由和权限必须双向一致。

[BRX-FE-CONTRACT-003] 发布制品必须通过 lock integrity、license、SCA、SBOM、签名、provenance、Federation artifact 和共享 Runtime 单实例检查。

[BRX-FE-CONTRACT-004] 文本 grep、`pnpm why` 或单一 ESLint 结果只能作为辅助证据，不能单独证明 deployed bundle 的 Runtime、路由、权限或安全上下文正确。

## 3. Layer 2A 契约清单（纯接口，长期稳定）

### 3.1 `UIAdapter` (41 个原子组件)

定义位置: `runtime-sdk-api-web/src/types/ui/adapter.ts`

[BRX-FE-UI-001] 官方插件和同 JS 权限域第三方插件必须通过 `useUI()` / BrixUI Contract 获取受治理组件，不得直接导入 MUI、Ant Design、Element Plus 或其他第三方 UI 库。

| 类别 | 组件 |
|---|---|
| 布局 | `Box`、`Stack`、`Paper`、`Container`、`Divider` |
| 排版 | `Typography` |
| 数据展示 | `Table`、`Tag`、`List`、`Empty`、`Pagination`、`Avatar`、`Badge`、`Card` |
| 表单 | `Input`、`Select`、`Checkbox`、`Switch`、`Radio`、`Form` |
| 反馈 | `Alert`、`Spin`、`Progress`、`Modal`、`Tooltip`、`Popover`、`Popconfirm`、`Message` |
| 导航 | `Menu`、`Tabs`、`Breadcrumb`、`Steps`、`Drawer`、`Collapse` |
| 基础 | `Button`、`Icon` |

> **禁止纳入**: `Sidebar` / `Header` / `Layout` — 这些是 Shell 层职责。

**Props 设计原则**：

[BRX-FE-UI-002] BrixUI 只定义跨实现稳定的语义组件和最小公共 Props；`sx`、厂商 Theme 类型和厂商枚举不得进入公共 Contract。

| 原则 | 说明 |
|---|---|
| **最小公共集** | Props 只取 MUI、Ant Design、Element Plus 三库的交集属性 |
| **语义化命名** | 使用 `variant="primary"` 而非 `variant="contained"`；`size="sm"` 而非 `size="small"` |
| **受控优先** | 表单组件统一提供 `value` + `onChange` 受控模式 |
| **扩展友好** | 预留 `className`、`style`；**禁止透传 `sx`**（MUI-only prop） |

---

> #### BrixUI：前端 UI 可替换性的核心机制（红线 FE-4）
>
> **`UIAdapter` 接口就是 BrixUI 的唯一抽象契约。** 插件通过 `useUI()` 取组件，永不感知底层 UI 库是什么。
>
> ```text
> Plugin 业务代码  (app-{name}-ui-web)
>   └─ const ui = useUI()
>             │通过 UIAdapter 契约 (L2A, runtime-sdk-api-web)
>             ▼
>   infra-adapter-ui-mui    ← 生产实现（@mui/material，当前默认）
>   infra-adapter-ui-native ← 零依赖轻量实现
>   infra-adapter-ui-antd   ← 可选扩展（需 RFC + 架构评审）
> ```
>
> **切换 UI 库 = 只改 Host 注入的 Adapter 一行配置，所有插件代码零改动。**
>
> BrixUI 未覆盖的组件必须提交 RFC 扩展。专业组件逃生舱必须在 UI Manifest 声明并通过安全、体积、许可和适配层评审；禁止 blanket exemption 或插件旁路引入第三方 UI 库（红线 **FE-4**，CI 阻断）。

### 3.2 `DesignTokens` (Brix 语义, 非 MUI 语义)

定义位置: `runtime-sdk-api-web/src/types/ui/design-tokens.ts`

[BRX-FE-UI-003] 颜色、间距、字体、圆角、阴影、动效和层级必须通过 `useTheme().tokens` 获取。插件不得直接导入原始平台设计令牌或重建平台级 ThemeTokens。

[BRX-FE-UI-004] 业务状态色可位于插件内部，但必须引用 Brix 语义令牌。专业组件逃生舱必须在 UI Manifest 声明，并通过安全、体积、许可和适配层评审。

```text
DesignTokens
├─ colors
│   ├─ brand        (primary/primaryLight/primaryDark/primaryContrast/secondary*)
│   ├─ surface      (page/card/raised/sunken/overlay)
│   ├─ text         (primary/secondary/disabled/inverse)
│   ├─ border       (default/strong/subtle/focus)
│   ├─ status       (success/warning/error/info + Light 变体)
│   └─ layout       (sidebar/header/divider)
├─ typography       (displayLarge … bodySmall … labelSmall)
├─ space            (xs / sm / md / lg / xl / xxl)
├─ spacing(n)       (函数, 8px 基数)
├─ shape            (sm/md/lg/full, string 类型如 '8px')
├─ shadows          (none/sm/md/lg/xl)
├─ breakpoints      (xs/sm/md/lg/xl)
├─ motion           (duration + easing)
└─ zIndex          (drawer/modal/popover/tooltip)
```

### 3.4 Shell 层布局组装规范

**核心约束**：`UIAdapter` 仅暴露**原子组件**；`AppSidebar`、`AppHeader`、`ProtectedLayout` 等布局组件由 `platform-frame-web` Shell 层通过 `useUI()` 取原子组件**组装**而成，永不进入适配器。

[BRX-FE-UI-005] 布局属于平台 Frame/Composition，不属于 UI Adapter 或业务插件；具体 UI Adapter 只实现原子组件。

```text
Host 配置: uiAdapter = muiAdapter | nativeAdapter
                    │
             UIProvider (Shell 层注入)
                    │
     ┌──────────────┼──────────────┐
     │              │              │
ProtectedLayout  AppSidebar    AppHeader
(Shell 组装)    useUI().Menu  useUI().Avatar
                useUI().Icon  useUI().Button
                    │
         infra-adapter-ui-{mui,native} 提供具体实现
```

| 组件类型 | 归属模块 | 红线 |
|---|---|---|
| 原子组件（`Button` / `Menu` / `Icon` 等） | `infra-adapter-ui-{mui,native}` | — |
| 布局组件（`AppSidebar` / `AppHeader` / `ProtectedLayout`） | `platform-frame-web/layouts` + `/components` | FE-4 / Host 依赖门禁 |
| 业务页面（`FooPage` 等） | `{name}-ui-web` 各插件 | — |

切换适配器（`muiAdapter` ↔ `nativeAdapter`）时，Shell 层布局组件**零改动**。

### 3.5 DesignTokenResolver 依赖注入模式

`ThemeCapabilityImpl` 通过构造注入 `DesignTokenResolver`，**不直接依赖** MUI 或任何 UI 库类型（Strategy 模式）。`platform-frame-web` 管理主题状态（mode/preset），具体令牌映射委托给 resolver。

```text
runtime-sdk-api-web ← 定义 DesignTokens + DesignTokenResolver 接口
        ▲                         ▲
        │                         │
platform-frame-web        infra-adapter-ui-mui
ThemeCapabilityImpl       MuiDesignTokenResolver
  getDesignTokens()  ←─注入─  resolve(mode): DesignTokens
```

| Resolver | 位置 | 令牌来源 |
|---|---|---|
| `MuiDesignTokenResolver` | `infra-adapter-ui-mui/src/theme/` | MUI `Theme` 对象内部结构 → Brix `DesignTokens` |
| `NativeDesignTokenResolver` | `infra-adapter-ui-native/src/theme/` | `ThemeTokens` 静态常量 → Brix `DesignTokens` |

**Runtime 装配原则**：

```text
Frontend BOM + Host Profile/Composition
  -> 选择一个 UI Adapter artifact
  -> Shared Runtime 按已校验声明解析唯一 Theme/UI provider
  -> 向插件注入 ThemeCapability / UI Contract
```

Host 不得在 `bootstrap.ts` 手写业务 Capability 注册、实例化插件实现或按 pluginId 分支。具体 Adapter 的选择属于 Profile/Composition；插件只消费 Contract。缺失、重复或版本不匹配必须在路由发布前 fail-fast。

Resolver 按 `mode` 缓存冻结的 `DesignTokens` 对象（O(1)）；`useTheme()` 内 `useMemo` 防止 React 重渲染。冻结策略：`Object.freeze()` shallow freeze + TypeScript `readonly` 递归双重保护。

## 4. 三层设计令牌体系（关键概念，记住它）

```text
Layer 1: Primitive Tokens (静态原语)
  📦 @brix-sdk/platform-design-tokens
  • 静态常量, 不响应暗色模式
  • 仅 platform-frame-web / infra-adapter-ui-* 可消费
  • ESLint: no-direct-design-tokens-import 禁止插件直接 import

Layer 2: Semantic Tokens (运行时语义)
  📦 runtime-sdk-api-web → DesignTokens 接口
  📦 platform-frame-web → ThemeCapabilityImpl 实现
  📦 infra-adapter-ui-{mui,native} → DesignTokenResolver 实现
  • 响应暗色/亮色 + 租户品牌
  • 插件唯一通过 useTheme().tokens 消费

Layer 3: Component Tokens (业务语义)
  📦 各插件 theme/ 目录
  • 仅允许业务领域语义色 (PARTNER_TYPE_COLORS, CASE_STATUS_COLORS)
  • 必须引用 Layer 2 (例: statusConfig.dot = tokens.colors.status.error)
  • ESLint: no-plugin-theme-tokens 禁止重定义平台令牌结构
```

## 5. 前端架构红线

前端专项红线使用独立 `FE-x` 编号，不复用根蓝图拥有的 A/S 编号，也不得放宽根蓝图。违反任一适用红线均阻断发布；仅有规则文件或单项测试通过不等于实现合规。

### 5.1 前端红线

| 红线 | 强制要求 | 最低门禁 |
|---|---|---|
| **FE-1** | Page/View 不得直接 HTTP、拼 URL、解析 JWT 或导入 Repository | ESLint import/call graph + component test |
| **FE-2** | Hook/ViewModel 不得直接传输、读取裸 Token 或绕过 Repository | ESLint + hook unit test |
| **FE-3** | Repository 只能经 Http/Query Capability，前后端只共享生成契约 | dependency rule + contract test |
| **FE-4** | 插件只能经 BrixUI/useUI 和语义 Design Tokens 使用 UI；逃生舱必须显式评审 | dependency + ESLint + UI Manifest |
| **FE-5** | React/Router/Auth/Theme/I18n/State 必须单实例；MF 禁止 `eager:true` 和隐式版本 | bundle artifact + runtime identity |
| **FE-6** | Platform/Actor/Subject/Bootstrap 上下文不得混用，Guard 不得替代后端授权 | Guard unit + browser E2E |
| **FE-7** | setup/reset/invite Token 不得持久化、进查询串或通过 referrer/log/telemetry 泄漏 | storage/log/referrer browser test |
| **FE-8** | 不可信 UI 不得进入同 JS 权限域；Module Federation 不是安全沙箱 | origin/iframe admission test |
| **FE-9** | UI Manifest、实际导出、路由、权限和 Host 能力必须双向一致 | schema + artifact + route snapshot |
| **FE-10** | 用户页面必须覆盖加载、错误、空状态、取消、重复提交和表单校验 | component/hook test |
| **FE-11** | 前端依赖必须通过许可证、SCA、lock integrity、SBOM、签名和 provenance 门禁 | supply-chain required check |
| **FE-12** | Frontend Host 只做静态组装和 Runtime 挂载，不得承载业务 Page/Hook/Repository | artifact graph + dependency guard |
| **FE-13** | 前端制品、浏览器存储、URL 和日志中不得出现 Access/Refresh Token；控制台与业务前端不得出现凭证输入（对应根 S-20、UI-018） | bundle scan + browser storage/DLP E2E + 页面清单 |

前端代码维护者不得单方修改或豁免红线。红线变更必须按根蓝图 §12.2/§12.3 走版本化 RFC、评审和同 PR 门禁；任何临时豁免必须满足根级到期与批准规则。

### 5.2 自动门禁映射

| 规则/门禁 | 对应红线 | 触发场景 |
|---|---|---|
| `@brix-architecture/frontend-layered-arch` | FE-1/FE-2/FE-3 | Page/Hook/Repository 跨层或直接网络调用 |
| `@brix-architecture/no-direct-ui-import` | FE-4 | 插件直接导入 `@mui/material`、Ant Design 等 |
| `@brix-architecture/no-plugin-theme-tokens` | FE-4 | 插件重建平台 Theme/Token 结构 |
| `@brix-architecture/no-direct-design-tokens-import` | FE-4 | 插件直接导入原语令牌 |
| `@brix-architecture/contract-layer-purity` | FE-3/FE-5 | Contract 层出现实现或厂商类型 |
| Federation artifact/runtime identity check | FE-5/FE-8/FE-9 | shared 配置、实例身份、远程入口不一致 |
| Browser Guard/DLP E2E | FE-6/FE-7/FE-10/FE-13 | 安全域混用、Token 泄漏、页面状态缺失、凭证页面出现在控制台 |
| SCA/license/SBOM/signature/provenance | FE-11 | 依赖或制品不满足供应链政策 |

上述规则名称是治理目标；规则尚不存在或未设为 required check 时必须标记 `missing-blocking`，不得据此宣称 Implementation Accepted。

## 6. 插件开发模板

```typescript
// app-foo/foo-ui-web/src/pages/FooPage.tsx
import { useUI, useTheme } from '@brix-sdk/runtime-sdk-react';
import { useFooPageModel } from '../hooks/useFooPageModel';

export const FooPage = () => {
  const ui = useUI();
  const { tokens } = useTheme();
  const model = useFooPageModel();

  if (model.loading) return <ui.Spin />;
  if (model.error) return <ui.Alert>{model.error.message}</ui.Alert>;
  if (model.items.length === 0) return <ui.Empty />;

  return (
    <ui.Card style={{ padding: tokens.space.md, borderRadius: tokens.shape.md }}>
      {model.items.map(item => (
        <ui.Tag key={item.id}>{item.label}</ui.Tag>
      ))}
    </ui.Card>
  );
};
```

```typescript
// app-foo/foo-ui-web/src/hooks/useFooPageModel.ts
import { useEffect, useState } from 'react';
import { useFooRepository } from '../repositories/FooRepositoryProvider';
import type { FooListItem, SafeUiError } from '../repositories/FooRepository';

interface FooPageState {
  readonly loading: boolean;
  readonly items: readonly FooListItem[];
  readonly error?: SafeUiError;
}

export const useFooPageModel = () => {
  const repository = useFooRepository();
  const [state, setState] = useState<FooPageState>({ loading: true, items: [] });

  useEffect(() => {
    const request = repository.list();
    request.result.then(items => setState({ loading: false, items, error: undefined }))
      .catch((error: SafeUiError) => setState({ loading: false, items: [], error }));
    return request.cancel;
  }, [repository]);

  return state;
};
```

Repository Provider 由插件 Composition 创建，Repository 内部只取得 Runtime 注入的 `HttpCapability` 或生成 Query client。Page 不导入 Repository；Hook 不创建 URL；Repository 不读取 Token。

**插件依赖规则**：

| 依赖 | 声明方式 |
|---|---|
| `@brix-sdk/shared-runtime-web`、`runtime-sdk-api-web`、`runtime-sdk-react` | peer dependency；版本范围由前端 BOM 生成 |
| React、ReactDOM、Router | peer dependency；由 Host 共享 Runtime 提供 |
| 本地联调 OSS artifact | 只允许受控 composite/workspace 开发配置，不得进入发布 POM/package metadata |
| UI 厂商、原语 Design Tokens | 插件 dependencies 禁止出现 |

发布制品不得包含 `link:`、`workspace:`、未锁定相对路径或本机绝对路径依赖。禁止出现 `@mui/material`、`@brix-sdk/platform-design-tokens`、`@emotion/*`。

### 6.1 MUI 违规引用修复指南

> 若代码审查发现 `@mui/material` 直接 import，按以下步骤修复。

| 步骤 | 操作 |
|---|---|
| **Step 1** | `package.json` 移除 `@mui/material`、`@mui/icons-material`、`@emotion/react`、`@emotion/styled` |
| **Step 2** | 组件函数体顶部：`const ui = useUI();` 替代直接 import 各组件 |
| **Step 3** | 所有 `sx={{ p: 2 }}` 改写为 `style={{ padding: tokens.space.md }}`（见附录 C 命名对照） |
| **Step 4** | MUI 属性语义映射：`variant="contained"` → `variant="primary"`；`Chip` → `ui.Tag`（见附录 B） |
| **Step 5** | 删除插件 `theme/` 下定义 `palette / shape / typography` 结构的 `xxxThemeTokens` 对象 |
| **Step 6** | 保留业务语义色常量（`PARTNER_TYPE_COLORS` 等）；其余改用 `tokens.colors.*` |

**迁移前后对比**：
```typescript
// ❌ Before — MUI 耦合
import { Box, Typography, Chip } from '@mui/material';
import { partnerThemeTokens } from '../theme';
const { palette, shape } = partnerThemeTokens;
// ...
<Box sx={{ p: 2, borderRadius: shape.borderRadius, bgcolor: palette.background.paper }}>
  <Typography variant="body1" color={palette.text.secondary}>{text}</Typography>
  <Chip label="标签" />
</Box>

// ✅ After — Brix 语义令牌
import { useUI, useTheme } from '@brix-sdk/runtime-sdk-react';
const ui = useUI();
const { tokens } = useTheme();
// ...
<ui.Box style={{ padding: tokens.space.md, borderRadius: tokens.shape.md, backgroundColor: tokens.colors.surface.card }}>
  <ui.Typography variant="bodyMedium" color={tokens.colors.text.secondary}>{text}</ui.Typography>
  <ui.Tag>标签</ui.Tag>
</ui.Box>
```

## 附录 D. 关键设计决策 FAQ

**Q1: 为何插件不能直接 `import from '@brix-sdk/platform-design-tokens'`？**
`@brix-sdk/platform-design-tokens` 是静态原语常量，不响应 dark mode 切换，也不响应租户品牌定制（SaaS 场景）。插件应通过 `useTheme().tokens` 获取运行时响应的语义令牌。

**Q2: 为何 `DesignTokens` 不复用 MUI `Theme` 类型？**
根蓝图要求插件只依赖稳定 Contract，厂商与基础设施实现隔离在 Adapter。`DesignTokens` 是 UI 无关合约（Brix 自有语义词汇）；MUI → Brix 的映射封装在 `infra-adapter-ui-mui` 中，换 Ant Design 只需增加经评审的 Adapter/Resolver，`platform-frame-web` 和业务插件不变。

**Q3: 为何 `shape` 值是 `string`（`'8px'`）而非 `number`（`8`）？**
插件 99% 场景是直接赋值 `borderRadius: tokens.shape.md`，不需要算术运算。`string` 类型消除了忘加 `px` 单位的 bug，与 Polaris / Salesforce Lightning Design System 对齐。需要算术运算时使用 `tokens.spacing(factor)` 函数。

**Q4: 为何 `typography` 用 `displayLarge ~ labelSmall` 而非 `h1 ~ h6`？**
`h1`~`h6` 是 HTML 文档结构标签名，不是视觉语义。同一个 `<h3>` 在 Hero 区可能是 40px，在卡片内是 18px。Brix 采用 Material Design 3 的 `display / title / body / label` 四档分类，设计师与开发者共用同一套语义词汇。

**Q5: 为何 `colors` 要分 `brand / surface / text / border / status / layout` 六组，而不是扁平结构？**
旧 `ThemeTokens` 的扁平 28 字段存在两个问题：(1) 残留 MUI 语义（`paper`、`divider`）在换 UI 库时语义不对；(2) 认知负荷过高（28 个字段全部并排）。分组后每组 2~8 个字段，符合 Miller's Law（7±2）；`surface.card` 自解释，`paper` 需要注释。

**Q6: Layout 组件（AppSidebar/AppHeader）为何不放进 UIAdapter？**
布局决策（导航层次、响应式折叠、品牌区域）是 Shell 层的产品关注点，不是 UI 库的关注点。若将 `MuiSidebar` 放进适配器，换 Native 适配器时 `NativeSidebar` 必须做一模一样的布局逻辑——这是错误的抽象。正确做法：Shell 层持有布局逻辑，从 `UIAdapter` 取原子组件渲染。

## 附录 E. 设计令牌命名体系与业界对标

以下对标说明了为何选择当前的 Brix 语义命名体系：

| 维度 | Shopify Polaris | Ant Design 5 | MUI | Salesforce Lightning | **Brix（当前）** |
|---|---|---|---|---|---|
| 原语层 | Polaris Tokens | Seed Tokens | MUI Theme defaults | Design Tokens | `@brix-sdk/platform-design-tokens` |
| 语义层 | CSS Custom Properties | Map Tokens via ConfigProvider | `useTheme()` | Design Tokens → LWC | `ThemeCapability.getDesignTokens()` |
| 消费方式 | `var(--p-color-bg)` | `token.colorPrimary` | `theme.palette.primary.main` | `var(--lwc-colorBrand)` | `tokens.colors.brand.primary` |
| 色彩分类 | bg / text / border / icon | colorBrand / colorText / colorBg | palette.primary / text / background | colorBrand / colorText | **brand / surface / text / border / status** |
| 字体命名 | headingLg / bodySm | — (fontSize scale) | h1~h6 / body1 | heading / body | **displayLarge ~ labelSmall** |
| 间距模型 | space-1 ~ space-12 | marginXS ~ marginXXL | spacing(factor) | spacingSmall ~ Large | **space.xs~xxl + spacing()** |
| 圆角类型 | string (`'4px'`) | number (4) | number (4) | string (`'0.25rem'`) | **string (`'4px'`)** |
| UI 库耦合度 | 无（CSS 变量） | 弱（token 对象） | 强（MUI Theme 对象） | 无（CSS 变量） | **无**（Brix 语义合约） |
| 暗色模式 | CSS 变量切换 | ConfigProvider.algorithm | ThemeProvider | CSS 变量切换 | `ThemeCapability` 运行时切换 |
| 令牌可替换 | ✅ | ✅ | ❌ | ✅ | ✅（换 Resolver 即可） |

**结论**：Brix 选择 `brand/surface/text/border/status` 色彩分类对齐 Polaris 和 Salesforce；选择 `displayLarge~labelSmall` 字体命名对齐 Material Design 3；选择 string 类型圆角对齐 Polaris/Lightning——整体设计去 MUI 耦合，与主流无耦合设计系统对齐。
