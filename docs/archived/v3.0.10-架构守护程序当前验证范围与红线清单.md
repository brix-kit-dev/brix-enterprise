## 2. 当前守护入口

### 2.1 Java ArchUnit 规则库

入口文件：

- `brix/packages/@brix/platform-devtools/architecture-guard/src/main/java/io/brix/architecture/guard/BrixArchitectureRules.java`

主要 profile：

| Profile | 目标对象 | 当前用途 |
| --- | --- | --- |
| `pluginProfile()` | 业务 Plugin | 插件通用 Java 静态红线 |
| `coreProfileV2()` | `*-core` 模块 | 组合 `PluginProfile`，并额外限制 core 的 Spring/Web/事务边界；当前 `app-booking` 和 `app-tenant` 使用它 |
| `hostProfile()` | Host | 极薄 Host 静态边界 |
| `adapterProfile()` | L2C Adapter | Adapter 隔离与三方类型泄漏 |
| `sdkProfile()` | Runtime SDK API | SDK API 纯度与实现依赖隔离 |
| `commonsProfile()` | platform-commons | commons 不反向依赖插件、Adapter、Host、Runtime 实现 |
| `operationalProfile()` | `platform-operational` | A-25/A-26 的平台运维边界 |
| `javaStaticBoundaryExecutor()` | 按 `moduleKind` 选择规则 | 面向治理注册表的字节码静态执行器 |

### 2.2 按 `moduleKind` 的 Java 静态执行器

入口文件：

- `brix/packages/@brix/platform-devtools/architecture-guard/src/main/java/io/brix/architecture/guard/executor/JavaStaticBoundaryExecutor.java`

当前按 `ModuleKind` 映射的主要检查：

| `moduleKind` | 当前检查重点 |
| --- | --- |
| `PLUGIN_API` | 禁 L0 基础设施 SDK、禁 L2B Runtime 实现、禁 Spring 容器 API |
| `PLUGIN_CORE` | 禁 Adapter/Kafka/直接 HTTP、禁 Spring 容器 API、禁 Runtime 实现、禁 HTTP binding、禁其他插件内部依赖、禁直接 JWT |
| `PLUGIN_SERVER` | 禁 Adapter/Kafka、禁 Spring 容器 API、禁 Runtime 实现、禁直接 JWT |
| `HOST` | Host 源码禁 Adapter 实现类型、L0 client、直接 HTTP、Capability bean、业务组件注解 |
| `ADAPTER` | Adapter 禁依赖插件内部；公共 API 禁泄漏第三方类型 |
| `RUNTIME_CAPABILITY` | Runtime capability 禁依赖插件、Host、L0 client |
| `PLATFORM_CAPABILITY` | Platform capability 禁依赖插件、Host、Spring 容器 API |
| `PLATFORM_OPERATIONAL` | Operational 模块禁插件内部、Adapter、通用 `CapabilityRegistry`、Spring MVC/Scheduled 旁路 |
| `SHARED_CONTRACT` / `UI_WEB` / `UI_MOBILE` | 当前 Java executor 不执行规则，前端另由 ESLint/制品门禁承担 |

### 2.3 前端 ESLint 架构规则

入口文件：

- `brix/packages/@brix/platform-devtools/eslint-config-architecture/index.js`
- `brix/packages/@brix/platform-devtools/eslint-config-architecture/rules/frontend-layer-boundary.js`

当前 ESLint 规则覆盖：

- 禁业务模块直接 import `@brix/infra-adapter-*`
- 禁直接 HTTP client：`axios`、`node-fetch`、`got`、`undici`、`ky`、`superagent`
- 禁直接中间件 client：Kafka、Redis、AMQP 相关包
- 禁直接 `fetch`
- 禁直接 `localStorage` / `sessionStorage`
- 禁 `console`
- 禁直接 EventEmitter / 第三方 event library
- Page/View/Component 不得直接 import Repository 或 business service
- Hook/ViewModel 不得直接使用传输、storage 或 token parsing
- Repository 不能依赖 React runtime hook；发 HTTP 时必须依赖注入 `HttpCapability` 或生成 typed client
- Frontend Host 源码不得 import 业务 Page/Hook/Repository/Service、provider policy 或 infra adapter
- 同 JS 权限域插件不得直接 import MUI/AntD/Element Plus/Chakra/Mantine 等 UI 库，必须走 BrixUI/useUI
- 禁插件定义平台级 ThemeTokens、直接 import primitive design tokens、使用 MUI-specific API
- 禁硬编码平台 role string literal
- 平台超管前端红线：禁止临时密码字段、platform-admin mode flag、`permission || true`
- 禁旧 `switchTenant(tenantId)` 流
- Runtime SDK web/mobile contract 层禁止导出对象、数组、字面量常量或 default object
- 可选导出的 `ultraThinHostRules` 约束前端 Host hook 的行数、复杂度、React Hook、循环、try/catch、复杂异步等

注意：`tenant-ui-web/eslint.config.cjs` 当前仍在注释中引用 v3.0.9，并且本轮 `lint` 在 TypeScript parser 阶段失败，说明该模块的前端架构 guard 尚不能形成有效执行证据。

## 8. 关键结论

1. 当前 Java 架构守护已经不是历史上的 `Tests run: 0` 空跑。守护库自身、`app-booking`、`app-tenant` 的 Java 后端规则都真实执行并通过。
2. 当前 Java guard 对 A-1、A-2、A-9、A-21、部分 A-6/A-8/A-10/A-13/A-17/A-24/A-25/A-26 有实际静态拦截能力。
3. 当前前端 guard 规则存在，并覆盖 A-7、A-18、FE-1/2/3/4/12 等静态边界，但 `tenant-ui-web` 还没有跑通 lint，因此不能算有效门禁证据。
4. 当前 guard 不能关闭 v3.0.10 的 Implementation Accepted。蓝图 §11.4 仍把多组实施门禁标记为 `missing-blocking` 或 `partial`，尤其是 Runtime 启动、完整入口发布、Outbox/Inbox 事务语义、安全负例、供应链和真实 Host/HTTP/DB/broker/browser 证据。
5. 架构守护程序必须继续保持通用性：它验证可复用红线，不应把 FIRST_OWNER 等业务流程硬编码成全局规则。FIRST_OWNER 应作为 multi-tenant 专项的 acceptance fixture，用来证明 Data Owner、事务、Outbox、幂等和权限边界。

## 9. 下一步建议

优先补齐以下缺口：

1. 修复 `tenant-ui-web` ESLint parser 配置，使前端架构规则可执行。
2. 将 `coreProfileV2()` 中仍指向 v3.0.9 / R1.1 adjudication 的说明重基线为 v3.0.10 表达，避免规则含义漂移。
3. 为 `JavaStaticBoundaryExecutor` 输出机器可读报告，包含 rule id、target cardinality、pass/fail、diagnostic code，避免只看 Maven 成功。
4. 增加 Manifest/Factory 双向一致性、`configure()` 禁副作用、Handler 创建时序、受管资源零残留的运行期负例。
5. 增加 A-10/T-24 的 Outbox/Inbox commit、receipt、relay、replay、duplicate-consumption 契约测试。
6. 增加 T-27/T-28 的配额行锁、FIRST_OWNER 接受事务、幂等/重放、rollback 后无脏状态测试。
