## 1. 概述

Brix 多租户遵循 **B2B2C Actor/Subject 双轨模型**：

| 概念 | JWT 角色 | 关键 Claim | 数据库表 |
|------|---------|-----------|---------|
| **Actor** (B 端成员) | `role=actor` | `mid` (memberId), `mtype` | `sys_tenant_member` |
| **Subject** (C 端 Principal) | `role=subject` | `pid` (principalId), `ptype` | `sys_tenant_principal` |

> **硬约束**: `mid` 和 `pid` 互斥——同一个 JWT 中绝不同时出现。

插件开发者主要消费三个能力契约：

- **TenantConfigCapability** — 三层合并配置（用户偏好 > 租户配置 > 平台默认）
- **PrincipalJoinedEvent** — Subject 加入租户时的领域事件
- **BusinessObjectCapability** — 可选契约，暴露 Subject 关联的业务对象

```xml
<dependency>

<!-- platform-tenant-api: 租户相关 DTO / Event -->
<dependency>
    <groupId>io.brix.platform</groupId>
    <artifactId>platform-tenant-api</artifactId>
    <version>${brix.version}</version>
</dependency>
```

**前端 (pnpm)**

```bash
# Web 端
pnpm add @brix-sdk/runtime-sdk-api-web @brix-sdk/runtime-sdk-react

# Mobile 端
pnpm add @brix-sdk/runtime-sdk-api-mobile @brix-sdk/platform-tenant-mobile
```

### 2.2 架构层级规则

```
Layer 4   enterprise-solutions (行业插件)
Layer 3   enterprise-host (商业运行壳)
Layer 2C  platform-tenant (多租户实现)
Layer 2A  runtime-sdk-api (能力契约)  ← 插件只依赖这一层
Layer 1   runtime-orchestrator
Layer 0   infrastructure
```

> **规则**: 插件 (Layer 4) 只能依赖 Layer 2A 的契约接口，不能直接依赖 Layer 2C 的实现类。

## 3. TenantConfigCapability — 租户配置能力

### 3.1 契约定义 (Layer 2A)

```java
/**
 * 租户配置能力契约.
 * 
 * 插件通过此接口获取租户级配置，无需关心配置来源。
 * 配置值按 用户偏好 > 租户配置 > 平台默认 的优先级合并。
 */
public interface TenantConfigCapability {

    /** 获取生效配置值（三层合并） */
    <T> T getEffectiveConfig(String key, Class<T> type);

    /** 获取生效配置值，带默认值 */
    <T> T getEffectiveConfig(String key, Class<T> type, T defaultValue);

    /** 获取租户配置（不含用户偏好覆盖） */
    <T> T getTenantConfig(String namespace, String key, Class<T> type);

    /** 批量获取某命名空间下所有配置 */
    Map<String, Object> getTenantConfigs(String namespace);

    /** 获取当前租户设置快照 */
    TenantSettings getTenantSettings();

    /** 获取当前生效的 Locale */
    Locale getEffectiveLocale();

    /** 获取当前生效的 TimeZone */
    ZoneId getEffectiveTimezone();

    /** 获取当前生效的 Theme */
    String getEffectiveTheme();
}
```

### 3.2 后端使用示例

```java
@Service
public class AppointmentService {

    private final TenantConfigCapability tenantConfig;

    public AppointmentService(TenantConfigCapability tenantConfig) {
        this.tenantConfig = tenantConfig;
    }

    public Duration getDefaultAppointmentDuration() {
        // 三层合并: 如果该租户配置了 30 分钟，但用户偏好设为 45 分钟，返回 45
        Integer minutes = tenantConfig.getEffectiveConfig(
                "reservation.defaultDuration", Integer.class, 30);
        return Duration.ofMinutes(minutes);
    }

    public String formatAppointmentDate(Instant appointmentTime) {
        ZoneId timezone = tenantConfig.getEffectiveTimezone();
        Locale locale = tenantConfig.getEffectiveLocale();
        return DateTimeFormatter
                .ofLocalizedDateTime(FormatStyle.MEDIUM)
                .withLocale(locale)
                .withZone(timezone)
                .format(appointmentTime);
    }

    public Map<String, Object> getReservationSettings() {
        // 批量获取 "reservation" 命名空间下的所有配置
        return tenantConfig.getTenantConfigs("reservation");
    }
}
```

### 3.3 前端使用示例 (React Web)

```tsx
import { useTenantConfig } from '@brix-sdk/runtime-sdk-react';

function SettingsPage() {
  const {
    effectiveConfig,
    userPreferences,
    branding,
    isLoading,
    updatePreferences,
    updateBranding,
  } = useTenantConfig();

  if (isLoading) return <Spinner />;

  return (
    <div>
      {/* 三层合并后的生效语言、来源 */}
      <p>
        当前语言: {effectiveConfig?.locale}
        (来源: {effectiveConfig?.localeSource})
      </p>

      {/* 用户偏好层覆盖 */}
      <button onClick={() => updatePreferences({ locale: 'en-US' })}>
        切换为英文
      </button>

      {/* 租户品牌 */}
      {branding && (
        <img src={branding.logoUrl} alt="Tenant Logo" />
      )}
    </div>
  );
}
```

### 3.4 配置 REST API

| 方法 | 端点 | 说明 |

| `GET` | `/api/v1/tenant/config/{namespace}` | 获取命名空间下的配置列表 |

## 4. PrincipalJoinedEvent — Subject 加入租户事件

### 4.1 事件定义 (Layer 2A)

```java
/**
 * Subject 加入租户时发布的领域事件.
 *
 * 触发时机:
 * - 租户员工手动邀请（后台添加患者/学员）
 * - Subject 接受邀请 / 确认加入租户
 * - Subject 完成注册并绑定租户
 * - 业务行为触发（如提交预约、完成报名时自动创建）
 *
 * ⚠️ 硬规则: 单纯浏览品牌页、扫码预览、访问公开链接，不自动发布此事件。
 */
public record PrincipalJoinedEvent(
    String tenantId,
    String principalId,
    String principalType,    // "PATIENT" | "CUSTOMER" | "STUDENT" 等
    String identityId,
    Instant joinedAt
) {}

/**
 * Subject 离开租户时发布的领域事件.
 */
public record PrincipalLeftEvent(
    String tenantId,
    String principalId,
    String reason,           // "SELF_EXIT" | "ADMIN_REVOKE" | "DISABLED"
    Instant leftAt
) {}
```

### 4.2 行业插件监听示例 — 医疗插件

```java
@Component
public class MedicalPrincipalEventListener {

    private final PatientService patientService;

    public MedicalPrincipalEventListener(PatientService patientService) {
        this.patientService = patientService;
    }

    /**
     * Subject 加入租户时，自动确保患者档案存在.
     *
     * 医疗插件监听通用领域事件，按需创建 medical_case 或
     * 患者档案，无需了解 platform-tenant 内部实现。
     */
    @EventListener
    public void onPrincipalJoined(PrincipalJoinedEvent event) {
        if ("CUSTOMER".equals(event.principalType())
                || "PATIENT".equals(event.principalType())) {
            patientService.ensurePatientRecord(
                    event.tenantId(), event.principalId());
        }
    }

    /**
     * Subject 离开租户时，标记患者档案为归档.
     *
     * ⚠️ 硬规则: Principal 的生命周期独立于单个 BusinessObject。
     * Case/Order/Enrollment 结束时，不自动删除或失效 Principal 记录。
     */
    @EventListener
    public void onPrincipalLeft(PrincipalLeftEvent event) {
        patientService.archivePatientRecord(
                event.tenantId(), event.principalId(), event.reason());
    }
}
```

### 4.3 行业插件监听示例 — 教育插件

```java
@Component
public class EducationPrincipalEventListener {

    private final EnrollmentService enrollmentService;

    public EducationPrincipalEventListener(EnrollmentService enrollmentService) {
        this.enrollmentService = enrollmentService;
    }

    @EventListener
    public void onPrincipalJoined(PrincipalJoinedEvent event) {
        if ("STUDENT".equals(event.principalType())) {
            enrollmentService.initializeStudentEnrollment(
                    event.tenantId(), event.principalId());
        }
    }
}
```

### 4.4 数据库表关联

```sql
-- 行业插件自建表，外键指向 sys_tenant_principal
CREATE TABLE medical_case (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id       VARCHAR(64) NOT NULL,
    patient_principal_id BIGINT NOT NULL REFERENCES sys_tenant_principal(id),
    doctor_member_id     BIGINT REFERENCES sys_tenant_member(id),
    case_type       VARCHAR(32) NOT NULL,
    status          VARCHAR(16) NOT NULL DEFAULT 'OPEN',
    created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_tenant_patient (tenant_id, patient_principal_id)
);
```

> **注意**: 所有行业表必须包含 `tenant_id` 列，用于数据隔离。

## 5. BusinessObjectCapability — 业务对象能力

### 5.1 契约定义 (Layer 2A)

```java
/**
 * 业务对象能力契约 — 可选（位于 runtime-sdk-api Layer 2A）.
 *
 * 让通用 UI 展示 Subject 关联的业务列表（如「我的病历」「我的订单」），
 * 而无需知道具体的行业数据模型。
 */
public interface BusinessObjectCapability {

    /**
     * 查询指定 Subject 关联的所有业务对象摘要.
     *
     * @param principalId sys_tenant_principal.id
     * @return 业务对象摘要列表
     */
    List<BusinessObjectSummary> listBySubject(String principalId);

    /**
     * 检查指定 Subject 是否存在活跃的业务关系.
     *
     * @param principalId sys_tenant_principal.id
     * @return true 如果存在至少一个活跃业务对象
     */
    boolean hasActiveBusinessRelation(String principalId);
}
```

```java
/**
 * 业务对象摘要 — 行业无关的通用数据结构.
 */
public class BusinessObjectSummary {
    /** 业务对象 ID */
    String id;
    /** 对象类型（插件自定义）: "medical_case" | "enrollment" | "order" */
    String objectType;
    /** 显示标题 */
    String title;
    /** 状态 */
    String status;
    /** 创建时间 */
    Instant createdAt;
    /** 更新时间 */
    Instant updatedAt;
    /** 扩展元数据 */
    Map<String, Object> metadata;
}
```

### 5.2 医疗插件实现示例

```java
@Service
public class MedicalBusinessObjectProvider implements BusinessObjectCapability {

    private final MedicalCaseRepository caseRepository;

    public MedicalBusinessObjectProvider(MedicalCaseRepository caseRepository) {
        this.caseRepository = caseRepository;
    }

    @Override
    public List<BusinessObjectSummary> listBySubject(String principalId) {
        return caseRepository.findByPatientPrincipalId(Long.valueOf(principalId))
                .stream()
                .map(this::toSummary)
                .toList();
    }

    @Override
    public boolean hasActiveBusinessRelation(String principalId) {
        return caseRepository.existsByPatientPrincipalIdAndStatusIn(
                Long.valueOf(principalId),
                List.of("OPEN", "IN_PROGRESS"));
    }

    private BusinessObjectSummary toSummary(MedicalCase medicalCase) {
        BusinessObjectSummary summary = new BusinessObjectSummary();
        summary.id = medicalCase.getId().toString();
        summary.objectType = "medical_case";
        summary.title = medicalCase.getCaseType() + " — " + medicalCase.getStatus();
        summary.status = medicalCase.getStatus();
        summary.createdAt = medicalCase.getCreatedAt();
        summary.updatedAt = medicalCase.getUpdatedAt();
        summary.metadata = Map.of(
                "caseType", medicalCase.getCaseType(),
                "doctorMemberId", String.valueOf(medicalCase.getDoctorMemberId())
        );
        return summary;
    }
}
```

### 5.3 通用 UI 消费示例

```tsx
import { useRuntimeContext } from '@brix-sdk/runtime-sdk-react';
import { useMemo, useEffect, useState } from 'react';

interface BusinessObjectSummary {
  id: string;
  objectType: string;
  title: string;
  status: string;
  createdAt: string;
  metadata: Record<string, unknown>;
}

/**
 * 通用业务对象列表组件.
 *
 * 通过 RuntimeContext 获取 BusinessObjectCapability 契约实现，
 * 自动展示当前 Subject 关联的所有业务对象。
 */
function SubjectBusinessObjects({ principalId }: { principalId: string }) {
  const context = useRuntimeContext();
  const [items, setItems] = useState<BusinessObjectSummary[]>([]);
  const [loading, setLoading] = useState(true);

  const capability = useMemo(() => {
    return context.getCapability<{
      listBySubject: (id: string) => Promise<BusinessObjectSummary[]>;
    }>(Symbol.for('BusinessObjectCapability'));
  }, [context]);

  useEffect(() => {
    if (!capability) {
      setLoading(false);
      return;
    }
    capability.listBySubject(principalId).then(result => {
      setItems(result);
      setLoading(false);
    });
  }, [capability, principalId]);

  if (loading) return <p>加载中...</p>;
  if (!capability) return <p>当前未安装业务插件</p>;
  if (items.length === 0) return <p>暂无业务记录</p>;

  return (
    <ul>
      {items.map(item => (
        <li key={item.id}>
          [{item.objectType}] {item.title} — {item.status}
        </li>
      ))}
    </ul>
  );
}
```

## 6. Mobile 端多租户集成

### 6.1 Provider 配置

```tsx
import {
  MobileTenantProvider,
  MobileTenantSelector,
  useMobileTenant,
} from '@brix-sdk/platform-tenant-mobile';

function App() {
  const getAuthToken = async () => {
    // 从 AuthCapability 获取当前 Token
    return authCapability.getAccessToken();
  };

  return (
    <MobileTenantProvider
      getAuthToken={getAuthToken}
      apiBaseUrl="/api/v1/tenant"
      secureStorage={secureStorageCapability}
      pushCapability={pushNotificationCapability}
      onTenantChange={(tenantId) => {
        console.log('Tenant changed to:', tenantId);
      }}
      onError={(error) => {
        console.error('Tenant error:', error);
      }}
    >
      <MainNavigator />
    </MobileTenantProvider>
  );
}
```

### 6.2 Hooks 使用

```tsx
import {
  useMobileTenant,
  useMobileTenantSwitch,
  useMobileTenantBranding,
  useMobileFeatureEnabled,
} from '@brix-sdk/platform-tenant-mobile';

function TenantDashboard() {
  const { tenant, availableTenants, isLoading } = useMobileTenant();
  const { switchTo, isSwitching } = useMobileTenantSwitch();
  const { branding, primaryColor } = useMobileTenantBranding();
  const hasMobileBranding = useMobileFeatureEnabled('mobile.branding');

  if (isLoading) return <ActivityIndicator />;

  return (
    <View style={{ backgroundColor: primaryColor }}>
      {hasMobileBranding && branding?.logoUrl && (
        <Image source={{ uri: branding.logoUrl }} />
      )}
      <Text>当前租户: {tenant?.name}</Text>
      <FlatList
        data={availableTenants}
        renderItem={({ item }) => (
          <TouchableOpacity
            onPress={() => switchTo(item.id)}
            disabled={isSwitching}
          >
            <Text>{item.name}</Text>
          </TouchableOpacity>
        )}
      />
    </View>
  );
}
```

### 6.3 推送通知租户路由

`platform-tenant-mobile` 自动通过 FCM Topic 订阅管理租户推送路由：

- 切换租户时自动: 退订旧 topic `tenant_{oldId}` + 订阅新 topic `tenant_{newId}`
- 推送 payload 中携带 `tenant_id` 和 `auto_switch_tenant` 字段
- 点击推送通知时自动解析并触发租户切换

## 7. 安全红线

以下 6 条安全红线在 E2E 测试中被强制验证（参见 `SecurityE2ETest.java`）:

| # | 红线 | 验证方式 |
|---|------|---------|
| 1 | **跨租户数据隔离**: Actor-A 不能访问 Tenant-B 数据 | Actor 持 Tenant-A token 请求 Tenant-B 数据 → 4xx |
| 2 | **Actor → Subject 提权**: Actor Token 不能调用 Subject-only 端点 | Actor token + Subject 端点 → 4xx |
| 3 | **Subject → Admin 提权**: Subject Token 不能调用管理 API | Subject token + 管理 API → 4xx |
| 4 | **JWT 互斥**: mid 和 pid 不能同时出现在一个 Token 中 | 含双标识的 Token → 403 |
| 5 | **租户欺骗**: Header 的 X-Tenant-ID ≠ JWT 的 tid → 拒绝 | Header 与 JWT 不一致 → 403 |
| 6 | **未认证访问**: 所有受保护端点必须要求 Bearer Token | 无 Token → 401 |
