## 0. TL;DR（执行摘要）

| 维度 | 决策 |
|------|------|
| **能力定位** | Super Admin 是 **平台级能力（Layer 2C）**，不是租户业务，不属于任何 enterprise-solutions 插件 |
| **代码位置** | 后端：`platform-commons/server/platform-admin`（新建）+ 已有 `platform-tenant`（实体） + 已有 `platform-auth`（登录与权限） |
| **架构红线** | 业务插件（enterprise-solutions/* / plugins/*）**禁止**依赖 `platform-admin`；超管能力**禁止**反向依赖任何业务插件 |
| **权限模型** | `RoleCode.PLATFORM_SUPER_ADMIN` + 细粒度 `PermissionCode.PLATFORM_*` 常量；接口放行**只校验 Permission**，不校验角色名字符串 |
| **身份模型** | 复用 `sys_identity` + `sys_platform_admin`；超管 Token 标记 `scope=PLATFORM`、`platform_role=SUPER_ADMIN`、不绑定 `tenant_id` |
| **MVP 范围** | 登录、列表、新增、禁用、重置密码、改自己密码、租户列表/状态、审计日志 |
| **不做** | 自定义角色编辑、MFA 完整流程、计费、配额、删除超管、邮件/短信通知 |

### 1.2 ⚠️ 架构耦合点（必须修正）

| # | 问题 | 影响 | 修正方案 |
|---|------|------|---------|
| C-1 | `PlatformAdminRole`（platform-tenant）依赖 `PlatformPermissions`（platform-auth）— Layer 2C 内部模块横向依赖 | 难以单独发布；语义混淆（"角色"逻辑落在租户模块） | 把 `PlatformAdminRole` + `PlatformPermissions` + `RoleCode` **下沉到 `platform-auth-api`**（纯接口/常量包，无 Spring 依赖） |
| C-2 | 当前没有 `PlatformAdminController`，若直接塞进 `platform-tenant` 会让租户管理与超管管理在同一模块膨胀 | 违反单一职责；后续 enterprise 业务想"嵌入"超管能力时无法剥离 | 新建 **`platform-admin`** 模块（Layer 2C）专门承载超管 REST 与 Service |
| C-3 | `enterprise-solutions/app-tenant/TenantManagementController` 当前持有 `/api/admin/tenants/*` — 与平台超管 API 路径混淆 | 会让"超管 = 租户 ADMIN"概念污染回流 | 把租户**生命周期管理**（创建/暂停/激活）迁移到 `platform-admin`，路径改为 `/api/platform/tenants/*`；`enterprise-solutions/app-tenant` 只保留**租户内**的设置/成员管理 |
| C-4 | 部分前端 hook 直接 `permissions.canX \|\| true` 临时绕过（见 [oauth-rbac-gap 备忘](../docs-dev/archived/...)）| 与"后端必须做权限校验"红线冲突的临时态 | 本期完成 RBAC seed 后**移除所有 `\|\| true`**（统一在落地任务 P-7 收尾） |
| C-5 | `LoginResponse.platformAdminMode` 是 enterprise app-identity 的 DTO 字段 | 业务插件 DTO 承载平台语义 | 由 `platform-admin-web` / `platform-auth-web` 提供平台登录 DTO，enterprise app-identity **不参与**平台超管登录 |

### 1.3 ✅ 与运行壳架构红线对照

#### 1.3a `AuditCapability` 分层归属

| 分层 | 内容 | 代码库位置 |
|------|------|----------|
| **Layer 2A（契约层）** | `AuditCapability` 接口，定义 `log(AuditEvent)` 签名；`AuditEvent` 值对象（无 Spring 依赖） | `brix/packages/@brix/runtime-sdk/runtime-sdk-api`（★ 新增） |

| 约束 6：Host 极薄 | ✅ 启用方式为 `pom.xml` 引入 `platform-admin` + YAML 配置；Host 零代码改动 |
| 约束 7：前后端完全分离 | ✅ `platform-admin-web` 走 View → Hook → Repository → HttpCapability |
| 约束 8：前端运行时唯一真相源 | ✅ `platform-admin-web` 只 peerDependency `@brix-sdk/shared-runtime-web` |

## 4. 权限码与角色码（常量定义）

新建 `platform-auth-api` 模块（无 Spring 依赖，纯常量）：

```java
package io.brix.platform.auth.api;

public final class RoleCode {
    public static final String PLATFORM_SUPER_ADMIN = "PLATFORM_SUPER_ADMIN";
    public static final String PLATFORM_ADMIN      = "PLATFORM_ADMIN";
    public static final String PLATFORM_AUDITOR    = "PLATFORM_AUDITOR";
    private RoleCode() {}
}

public final class PermissionCode {
    /**
     * 内部旁路权限（platform:bypass）—— 使用边界严格约束，见 §4.1。
     *
     * ✅ 允许：PermissionAspect 内部检测；JwtIssuerCapability 为 SUPER_ADMIN 签发 Token 时写入
     * ❌ 禁止：业务插件消费；任何 @RequirePermission 注解引用；前端 UI 可见性控制
     */
    public static final String BYPASS                        = "platform:bypass";
    public static final String PLATFORM_ADMIN_READ           = "platform:admin:read";
    public static final String PLATFORM_ADMIN_CREATE         = "platform:admin:create";
    public static final String PLATFORM_ADMIN_DISABLE        = "platform:admin:disable";
    public static final String PLATFORM_ADMIN_RESET_PWD      = "platform:admin:reset-password";
    public static final String PLATFORM_ADMIN_CHANGE_OWN     = "platform:admin:change-own-password";
    public static final String PLATFORM_AUDIT_READ           = "platform:audit:read";
    public static final String PLATFORM_TENANT_READ          = "platform:tenant:read";
    public static final String PLATFORM_TENANT_UPDATE_STATUS = "platform:tenant:update-status";
    private PermissionCode() {}
}
```

### 4.1 `platform:bypass` 使用边界

`bypass` 的语义是「此 Token 已经过平台最高级别身份验证，权限框架内部可跳过细粒度逐条检查」，**不等于**「该用户有权做任意业务操作」。

| 场景 | 是否允许 |
|------|----------|
| `PermissionAspect` 内部读取，检测当前用户是否持有 bypass 从而免逐权限校验 | ✅ |
| `JwtIssuerCapability` 为 `SUPER_ADMIN` Token 签发时写入该权限码 | ✅ |
| 单元测试构造 mock JWT 携带此码以验证 bypass 逻辑 | ✅ |
| `enterprise-solutions/*` 任意插件 `hasPermission(PermissionCode.BYPASS)` | ❌ R-3a |
| 任意接口使用 `@RequirePermission(PermissionCode.BYPASS)` 做门控 | ❌ R-3b |
| 前端 `permissions.includes('platform:bypass')` 控制页面元素可见性 | ❌ R-3c |

> 前端 UI 控制**必须**依赖具体 `platform:*` 权限码（如 `PLATFORM_ADMIN_CREATE`）；持有 bypass 不代表 UI 展示全部功能入口。

每条审计落库字段（统一接入 `AuditService.log(AuditEvent)`）：

| 字段 | 必填 | 说明 |
|------|------|------|
| `actor_identity_id` | ✅ | 操作者 identity（来自 `AuthenticatedUser`） |
| `action` | ✅ | `AuditAction.*` 常量 |
| `target_type` | ✅ | `PLATFORM_ADMIN` / `TENANT` / `SELF` |
| `target_id` | ⛅ | 被操作对象 id |

| `ip` | ✅ | 来自请求 |
| `user_agent` | ✅ | 来自请求 Header |
| `result` | ✅ | `SUCCESS` / `FAILURE` |
| `reason` | ⛅ | 失败原因或操作备注 |
| `request_id` | ✅ | 链路追踪 ID |
| `created_at` | ✅ | 服务端时间 |

> **红线**：禁止把 `password`、`token`、`secret` 写入 `reason` 或任何审计字段。

## 6. 后端接口规约

| # | 方法 | 路径 | 权限 | 说明 |
|---|------|------|------|------|
| 1 | POST | `/api/platform/auth/login` | 匿名 | 平台超管登录；返回 `accessToken`(scope=PLATFORM) + `forcePasswordChange` 标志 |
| 2 | POST | `/api/platform/auth/logout` | 已登录 | 撤销当前 Token |
| 3 | GET  | `/api/platform/admins` | `platform:admin:read` | 分页查询超管列表 |
| 4 | POST | `/api/platform/admins` | `platform:admin:create` | 新增超管，默认 `force_password_change=true` |
| 5 | PATCH| `/api/platform/admins/{id}/disable` | `platform:admin:disable` | 禁用，校验非"最后一个 ACTIVE 超管" |
| 6 | POST | `/api/platform/admins/{id}/reset-password` | `platform:admin:reset-password` | 生成临时密码（一次性返回，仅本次响应可见），设置 `force_password_change=true` |
| 7 | POST | `/api/platform/admins/me/change-password` | `platform:admin:change-own-password` | 校验旧密码 → 设置新密码 → 失效旧 Token |
| 8 | GET  | `/api/platform/audit-logs` | `platform:audit:read` | 分页 + 时间/动作/操作者过滤 |
| 9 | GET  | `/api/platform/tenants` | `platform:tenant:read` | 平台视角租户列表 |
| 10| PATCH| `/api/platform/tenants/{id}/status` | `platform:tenant:update-status` | 激活/暂停/恢复，发布 `TenantStatusChangedEvent` |

**统一约束**：
- 全部接口走 `platform-gateway` 路由 `/api/platform/**`，与租户业务路径完全隔离
- 全部使用 `@RequirePermission(PermissionCode.XXX)` 注解，不写 `@RequireRole`
- DTO 定义在 `platform-admin/dto/`，前端通过 OpenAPI / TypeScript 类型同步
- 所有响应不返回 `passwordHash`、`mfaSecret` 等敏感字段（DTO 显式 whitelist）

## 7. 登录 Token 设计

```jsonc
// JWT Payload (PLATFORM scope)
{
  "sub": "<identity_id>",
  "scope": "PLATFORM",            // ★ 与租户 Token 区分
  "platform_role": "SUPER_ADMIN", // 来自 sys_platform_admin.role
  "permissions": [                // 由 RBAC 解析后下放，前端 UI 控制用
    "platform:bypass",
    "platform:admin:create",
    ...
  ],
  "force_password_change": true,  // 强制改密标记
  "iat": 1700000000,
  "exp": 1700003600,              // 默认 1 小时
  "jti": "<uuid>"                 // 用于改密/登出主动失效
}
```

**红线**：
- ❌ 平台超管 Token 中**禁止**出现 `tenant_id` claim
- ❌ 业务插件**禁止**自行解析 JWT；必须通过 `AuthContextCapability.currentUser()`
- ❌ Token 刷新机制 MVP 不做，过期即重登
- ✅ 改密/禁用必须使旧 Token 失效（基于 `jti` 黑名单或 `password_updated_at` 校验）

## 8. 关键业务流程

### 8.1 登录流程
```
Client → POST /api/platform/auth/login {username, password}
  → PlatformAuthController
  → AuthFlowCapability.login(LoginCommand{scope=PLATFORM})
    ├─ IdentityTenantCapability.findIdentityByUsername()
    ├─ PasswordHashCapability.matches()
    ├─ 失败 → AuditAction.SUPER_ADMIN_LOGIN_FAILED + 累计 failed_login_count
    └─ 成功 → 校验 sys_platform_admin.status=ACTIVE
              → JwtIssuerCapability.issuePlatformAdminToken()
              → AuditAction.SUPER_ADMIN_LOGIN_SUCCESS
              → 返回 LoginResponse{accessToken, forcePasswordChange, platformRole, permissions}
```

### 8.2 新增超管流程
```
Client → POST /api/platform/admins {username, email, role, notes}
  → PlatformAdminController.@RequirePermission(PLATFORM_ADMIN_CREATE)
  → PlatformAdminService.create()
    ├─ 校验 identity 不存在或未关联超管
    ├─ 生成临时密码（PasswordGenerator）
    ├─ 创建 sys_identity（force_password_change=true）
    ├─ 创建 sys_platform_admin（status=ACTIVE, created_by=current）
    ├─ 绑定 sys_identity_role_assignment（scope=PLATFORM, role=PLATFORM_SUPER_ADMIN）
    ├─ AuditAction.SUPER_ADMIN_CREATED
    └─ 发布 SuperAdminCreatedEvent (DomainEvent)
  → 响应 { id, tempPassword }   // ★ 仅本次响应明文返回，落库为哈希
```

### 8.3 禁用超管流程
```
Client → PATCH /api/platform/admins/{id}/disable {reason}
  → PlatformAdminService.disable()
    ├─ 校验：count(status=ACTIVE) > 1 否则拒绝（"禁止禁用最后一个 ACTIVE 超管"）
    ├─ 校验：不能禁用自己
    ├─ status=DISABLED, disabled_at, disabled_by, disable_reason
    ├─ 撤销该 identity 全部活跃 Token（基于 jti 黑名单）
    └─ AuditAction.SUPER_ADMIN_DISABLED
```

### 8.4 重置密码流程
```
Client → POST /api/platform/admins/{id}/reset-password
  → PlatformAdminService.resetPassword()
    ├─ 生成临时密码 (≥12位，含大小写字母+数字+符号，由 SecureRandom 产生)
    │   • 明文临时密码：内存持有，仅写入一次响应，绝不落库、绝不入审计
    │   • 过期时间：temp_password_expires_at = now + 24h（V012 新增字段），
    │     首次登录后服务端立即将该字段置 NULL
    │   • 生产演进方向：v1.1 优先切换为一次性重置链接（UUID token + 24h TTL，
    │     绕过"响应中返回明文"的安全敞口），本 MVP 接口签名已预留 resetMode 字段
    ├─ PasswordHashCapability.hash(tempPassword) → 更新 passwordHash
    ├─ 更新 sys_identity:
    │   - force_password_change = true
    │   - password_updated_at = now
    │   - temp_password_expires_at = now + 24h
    ├─ 撤销该 identity 全部活跃 Token（jti 黑名单）
    └─ AuditAction.SUPER_ADMIN_PASSWORD_RESET
        ← reason 字段只写「密码已重置」，禁止含任何密码内容
  → 响应 { tempPassword }   // ★ 仅本次响应明文可见；前端展示即销毁，不缓存
```

> **临时密码安全红线**：
> - ❌ 禁止将临时密码（明文或密文）写入 `biz_audit_log.reason` 或任何日志
> - ❌ 禁止临时密码过期后仍可使用（服务端登录时校验 `temp_password_expires_at < now`）
> - ✅ 首次登录若 `force_password_change=true`，全局拦截器只放行 `/admins/me/change-password`，其余接口返回 423 Locked
> - ✅ 生产里程碑：v1.1 演进为「一次性重置链接」，本 MVP 不阻塞施工

### 8.5 修改自己密码流程
```
Client → POST /api/platform/admins/me/change-password {oldPassword, newPassword}
  → 校验 newPassword 强度（PasswordPolicyService）
  → PasswordHashCapability.matches(oldPassword)
  → 更新 hash + force_password_change=false + password_updated_at=now
  → 撤销当前 jti 之外的全部 Token
  → AuditAction.SUPER_ADMIN_PASSWORD_CHANGED
```

### 8.6 租户状态变更流程
```
Client → PATCH /api/platform/tenants/{id}/status {status: SUSPENDED, reason}
  → 校验目标状态合法（ACTIVE / SUSPENDED / 恢复）
  → TenantProvisioningService.updateStatus()
  → AuditAction.TENANT_STATUS_CHANGED
  → EventBusCapability.publish(TenantStatusChangedEvent)   // 业务插件按需订阅
```

## 10. 安全控制点清单

| # | 控制点 | 实现位置 |
|---|--------|---------|
| S-1 | 密码 BCrypt（cost ≥ 12）哈希存储 | `PasswordHashCapabilityImpl` |
| S-2 | 全部接口后端权限校验（`@RequirePermission`） | `PermissionAspect` |
| S-3 | 登录失败计数 + 阶梯锁定（5 次锁 15 分钟） | `PlatformAuthService` |
| S-4 | 登录成功/失败均落审计 | `PlatformAuthController` |
| S-5 | 临时密码强度 ≥12 位、字母+数字+符号 | `PasswordGenerator` |
| S-6 | force_password_change=true 时仅放行改密接口 | 全局拦截器 |
| S-7 | Token TTL 默认 1h；改密/禁用立即失效 | `JwtIssuerCapability` + `TokenBlacklist` |
| S-8 | 敏感字段不入日志（password/token/secret） | `LoggingScrubFilter` |
| S-9 | 禁止禁用最后一个 ACTIVE 超管 | `PlatformAdminService.disable()` |
| S-10| 禁止删除超管（MVP 不实现 DELETE 接口） | 不暴露端点 |
| S-11| 临时密码仅在创建/重置响应中返回一次，不落 audit reason | `PlatformAdminService` |
| S-12| 平台 Token 与租户 Token 通过 `scope` claim 严格区分 | `JwtValidator` |

## 11. 不允许违反的架构红线

| # | 红线 | 检查方式 |
|---|------|---------|
| R-1 | 业务插件（enterprise-solutions/* / plugins/*）**禁止**依赖 `platform-admin` | `architecture-guard` ArchUnit 测试 |
| R-2 | `platform-admin` **禁止**反向依赖任何 `enterprise-*` 模块 | 同上 |
| R-3 | 代码中**禁止**以字符串字面量做权限判断（如 `role.equals("SUPER_ADMIN")`）；必须引用 `RoleCode.*` 常量。**允许出现**的场景：`RoleCode`/`PlatformAdminRole` 枚举定义体内、RBAC Seed SQL、JWT claim 读写（`platform_role` claim 值）、单元/集成/验收测试断言。其余代码中若 grep 到裸字符串 `"SUPER_ADMIN"` / `"super admin"` 则 CI 失败 | ESLint `no-role-string-literal` + ArchUnit `noStringRoleCheck` |
| R-4 | 业务插件**禁止**自行解析 JWT、自行实现密码加密 | `no-direct-jwt-import` lint |
| R-5 | Host **禁止**写超管业务逻辑；启用方式仅 pom + YAML | 代码 review |
| R-6 | 前端**禁止**直接 `fetch/axios`；所有调用走 `Repository → HttpCapability` | `no-direct-http-import` lint |
| R-7 | 前端**禁止**直接 `import 'antd'/'@mui/material'`；走 `useUI()` | `no-direct-ui-import` lint |
| R-8 | `sys_tenant_member` **禁止**承载平台超管角色 | DB 触发器或代码 review |
| R-9 | 平台超管 Token **禁止**包含 `tenant_id` claim | `JwtValidator` 单元测试 |
| R-10| 任何敏感字段（password/token/secret）**禁止**写入审计 `reason` 或日志 | `LoggingScrubFilter` 单元测试 |
