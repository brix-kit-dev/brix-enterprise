## 第一层：数据库骨架（不可推翻）

### Feature 1: 统一资源归属模型（Ownership Model）

**目标**：为所有租户业务数据提供统一的数据归属结构

**为什么必须现在做**：
```text
当前只有 tenant_id，未来会需要：

租户
  └ 组织
      └ 成员
          └ 数据归属

如果现在不预留字段，未来需要全表迁移。
```

**技术规格**：

所有租户业务表必须包含以下字段：

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `tenant_id` | BIGINT | ✅ | 当前租户 |
| `owner_member_id` | BIGINT | ◻️ 可空 | 数据归属成员 |
| `owner_org_id` | BIGINT | ◻️ 可空 | 数据归属组织 |
| `created_by` | BIGINT | ✅ | 创建人 |
| `created_at` | TIMESTAMP | ✅ | 创建时间 |

**示例 DDL**：
```sql
-- 业务表模板
CREATE TABLE biz_xxx (
    id BIGINT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    owner_member_id BIGINT,          -- 可空，预留
    owner_org_id BIGINT,             -- 可空，预留
    created_by BIGINT NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    -- 业务字段...
    INDEX idx_tenant (tenant_id),
    INDEX idx_owner_member (owner_member_id),
    INDEX idx_owner_org (owner_org_id)
);
```

**验收标准**：
- [ ] 所有业务表包含 `tenant_id` + `created_by` + `created_at`
- [ ] 所有业务表预留 `owner_member_id` + `owner_org_id`（可空）

### Feature 7: Snowflake ID

**目标**：统一 ID 类型，避免 UUID 导致索引膨胀

**为什么必须现在做**：
- ID 类型一旦上线无法修改
- UUID (36字节) vs BIGINT (8字节) 索引大小差 4.5 倍
- 高并发场景性能差异明显

**技术规格**：

| 表 | ID 字段 | 类型 |
|-----|---------|------|
| `sys_tenant` | id | BIGINT |
| `sys_identity` | id | BIGINT |
| `sys_tenant_member` | id | BIGINT |
| `sys_platform_admin` | id | BIGINT |
| `biz_*` | id | BIGINT |

**Java 实现**：
```java
public interface IdGenerator {
    long nextId();
}

// 使用
@Component
public class SnowflakeIdGenerator implements IdGenerator {
    // 基于 Snowflake 算法
}
```

**验收标准**：
- [ ] 所有核心表 ID 类型为 BIGINT
- [ ] IdGenerator 接口统一生成 ID

### Feature 10: 枚举冻结（Enum Freeze）

**目标**：确保核心枚举值稳定，只能扩展不能改名

**为什么必须现在做**：
- 枚举值一旦存入数据库，改名会导致现有数据不兼容
- 需要在第一天约定好，后续只能新增不能删改

**技术规格**：

**冻结枚举列表**：

```java
/**
 * 租户状态（冻结）
 * ⚠️ 只能新增，不能删除或改名
 */
public enum TenantStatus {
    ACTIVE,      // 正常
    SUSPENDED,   // 暂停
    PENDING,     // 待激活（预留）
    ARCHIVED     // 归档（预留）
}

/**
 * 租户成员类型（冻结）
 * ⚠️ 只能新增，不能删除或改名
 */
public enum TenantMemberType {
    OWNER,       // 所有者（每个租户唯一）
    ADMIN,       // 管理员
    MEMBER,      // 普通成员
    CUSTOMER     // 客户（如患者）
}

/**
 * 平台管理员角色（冻结）
 * ⚠️ 只能新增，不能删除或改名
 */
public enum PlatformAdminRole {
    SUPER_ADMIN,     // 超级管理员
    PLATFORM_ADMIN   // 平台管理员
}

/**
 * 通用状态（冻结）
 * ⚠️ 只能新增，不能删除或改名
 */
public enum MemberStatus {
    ACTIVE,      // 正常
    DISABLED,    // 禁用
    PENDING      // 待激活
}
```

**枚举管理规则**：
| 操作 | 允许 | 原因 |
|------|------|------|
| 新增枚举值 | ✅ | 向后兼容 |
| 删除枚举值 | ❌ | 现有数据会失效 |
| 重命名枚举值 | ❌ | 数据库存的是字符串 |
| 调整顺序 | ✅ | 不影响存储 |

**验收标准**：
- [ ] 枚举类定义完成，带 `@Frozen` 注释
- [ ] 代码评审 Checklist 包含枚举检查
- [ ] 禁止在枚举上使用 `@JsonValue` 数字映射

### Feature 11: 唯一键规则（Tenant-Scoped Unique）

**目标**：确保租户内唯一约束正确

**为什么必须现在做**：
- 数据库约束一旦创建，后期修改需要重建索引
- 不带 `tenant_id` 的唯一约束会导致跨租户冲突

**技术规格**：

**规则：租户业务表的唯一约束必须包含 `tenant_id`**

```sql
-- ❌ 错误：跨租户冲突
CREATE TABLE biz_case (
    id BIGINT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    case_no VARCHAR(50) NOT NULL,
    UNIQUE KEY uk_case_no (case_no)  -- 租户A的001会和租户B的001冲突
);

-- ✅ 正确：租户内唯一
CREATE TABLE biz_case (
    id BIGINT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    case_no VARCHAR(50) NOT NULL,
    UNIQUE KEY uk_tenant_case_no (tenant_id, case_no)  -- 每个租户独立编号
);
```

**唯一键命名规范**：
| 类型 | 命名规范 | 示例 |
|------|---------|------|
| 系统表唯一键 | `uk_{field}` | `uk_code` |
| 业务表唯一键 | `uk_tenant_{field}` | `uk_tenant_case_no` |

**例外（无需 tenant_id）**：
- `sys_tenant.code` - 租户编码全局唯一
- `sys_identity.phone` - 手机号全局唯一
- `sys_identity.email` - 邮箱全局唯一

**验收标准**：
- [ ] 所有业务表唯一约束包含 `tenant_id`
- [ ] DDL Review Checklist 包含唯一键检查

### Feature 13: 系统表白名单（Tenant-Exempt Whitelist）

**目标**：明确哪些表不需要 `tenant_id`

**为什么必须现在做**：
- 架构规则需要开发初期明确
- 否则后续难以追溯哪些表漏加了 `tenant_id`

**技术规格**：

**白名单表（无需 tenant_id）**：

| 表名 | 原因 |
|------|------|
| `sys_tenant` | 租户表本身 |
| `sys_identity` | 全局身份表 |
| `sys_tenant_member` | 关系表，有 tenant_id 字段 |
| `sys_platform_admin` | 平台管理员，超越租户 |
| `sys_identity_oauth` | OAuth 绑定，关联 identity |
| `sys_config` | 平台级配置 |
| `sys_migration` | 数据库迁移记录 |

**非白名单表必须**：
1. 包含 `tenant_id BIGINT NOT NULL` 字段
2. 建立 `INDEX idx_tenant (tenant_id)` 索引
3. 被 TenantInterceptor 自动过滤

**代码实现**：
```java
public class TenantWhitelist {
    
    private static final Set<String> EXEMPT_TABLES = Set.of(
        "sys_tenant",
        "sys_identity",
        "sys_tenant_member",
        "sys_platform_admin",
        "sys_identity_oauth",
        "sys_config",
        "sys_migration"
    );
    
    public static boolean isExempt(String tableName) {
        return EXEMPT_TABLES.contains(tableName.toLowerCase());
    }
}
```

**验收标准**：
- [ ] 白名单表列表确定
- [ ] TenantInterceptor 跳过白名单表
- [ ] TenantSqlGuard 跳过白名单表
- [ ] 新建表必须在代码评审中说明是否加入白名单

## 第二层：安全模型（必须）

### Feature 6: 租户真相源（Tenant Source of Truth）

**目标**：避免租户身份判定混乱

**问题场景**：
```text
❌ 危险情况：
   URL: tenant=A
   Header: X-Tenant-Id=B
   Token: tid=C

谁才是真正的租户？
```

**技术规格**：

**规则 1：已认证请求只信任 JWT**
```java
// 已认证请求
if (jwtToken != null) {
    tenantId = jwtToken.getClaim("tid");
    // 忽略其他来源
}
```

**规则 2：租户解析优先级**
```text
1. JWT Token (tid claim)     ← 已认证请求唯一真相
2. Header (X-Tenant-Id)      ← 服务间调用
3. Subdomain (xxx.app.com)   ← Web 访问
4. Path (/api/t/{code}/...)  ← API 路由
5. Query (?tenant=xxx)       ← 调试/测试
6. Default                   ← 开发环境
```

**规则 3：冲突检测**
```java
// 如果已认证，但请求带了不同租户
if (jwtTenantId != null && headerTenantId != null) {
    if (!jwtTenantId.equals(headerTenantId)) {
        throw new TenantMismatchException();
        // HTTP 403 TENANT_MISMATCH
    }
}
```

**验收标准**：
- [ ] TenantResolverChain 实现优先级解析
- [ ] 跨租户请求返回 403 TENANT_MISMATCH
- [ ] 单元测试覆盖各种冲突场景

### Feature 5: 租户上下文传播（Async/MQ）

**目标**：确保异步任务不丢失租户上下文

**问题场景**：
```java
// ❌ 错误：异步任务丢失上下文
@Async
public void processCase(Long caseId) {
    // TenantContext.getCurrentTenantId() = null !!!
}
```

**技术规格**：

```java
public final class TenantContext {
    private static final ThreadLocal<TenantInfo> CONTEXT = new ThreadLocal<>();
    
    // 基础 API
    public static Long getCurrentTenantId() { ... }
    public static TenantInfo getCurrentTenant() { ... }
    public static void setCurrentTenant(TenantInfo tenant) { ... }
    public static void clear() { ... }
    
    // 传播 API
    public static Runnable wrap(Runnable runnable) {
        TenantInfo tenant = getCurrentTenant();
        return () -> {
            try {
                setCurrentTenant(tenant);
                runnable.run();
            } finally {
                clear();
            }
        };
    }
    
    public static <T> Callable<T> wrap(Callable<T> callable) {
        TenantInfo tenant = getCurrentTenant();
        return () -> {
            try {
                setCurrentTenant(tenant);
                return callable.call();
            } finally {
                clear();
            }
        };
    }
}
```

**使用示例**：
```java
// ThreadPool
executor.submit(TenantContext.wrap(() -> {
    // 可以正确获取租户
    Long tenantId = TenantContext.getCurrentTenantId();
}));

// @Async（需要装饰器）
@Bean
public TaskDecorator tenantTaskDecorator() {
    return runnable -> TenantContext.wrap(runnable);
}
```

**验收标准**：
- [ ] TenantContext.wrap(Runnable) 实现
- [ ] TenantContext.wrap(Callable) 实现
- [ ] TenantTaskDecorator 用于 @Async
- [ ] 异步任务中 TenantContext.getCurrentTenantId() 正确

### Feature 12: 引用一致性校验（Reference Consistency）

**目标**：确保 `owner_member_id` / `owner_org_id` / `created_by` 引用的对象属于同一租户

**为什么必须做**：
- 防止跨租户数据污染
- 防止权限绕过攻击

**问题场景**：
```text
❌ 危险情况：
   租户 A 创建 Case，但 owner_member_id 指向租户 B 的成员
   → 数据归属混乱，权限无法正确判断
```

**技术规格**：

**Service 层校验规则**：
```java
public class TenantReferenceValidator {
    
    @Autowired
    private TenantMemberRepository memberRepository;
    
    @Autowired
    private OrganizationRepository organizationRepository;
    
    /**
     * 校验 member 是否属于当前租户
     */
    public void validateMemberBelongsToTenant(Long memberId) {
        if (memberId == null) return;
        
        Long currentTenantId = TenantContext.getCurrentTenantId();
        TenantMember member = memberRepository.findById(memberId)
            .orElseThrow(() -> new InvalidReferenceException("Member not found: " + memberId));
        
        if (!member.getTenantId().equals(currentTenantId)) {
            throw new CrossTenantReferenceException(
                "Member " + memberId + " does not belong to tenant " + currentTenantId
            );
        }
    }
    
    /**
     * 校验 organization 是否属于当前租户
     */
    public void validateOrgBelongsToTenant(Long orgId) {
        if (orgId == null) return;
        
        Long currentTenantId = TenantContext.getCurrentTenantId();
        Organization org = organizationRepository.findById(orgId)
            .orElseThrow(() -> new InvalidReferenceException("Organization not found: " + orgId));
        
        if (!org.getTenantId().equals(currentTenantId)) {
            throw new CrossTenantReferenceException(
                "Organization " + orgId + " does not belong to tenant " + currentTenantId
            );
        }
    }
    
    /**
     * 批量校验业务实体的引用字段
     */
    public void validateOwnership(TenantOwnedEntity entity) {
        validateMemberBelongsToTenant(entity.getOwnerMemberId());
        validateOrgBelongsToTenant(entity.getOwnerOrgId());
        validateMemberBelongsToTenant(entity.getCreatedBy());
    }
}
```

**使用方式**：
```java
@Service
public class CaseServiceImpl implements CaseService {
    
    @Autowired
    private TenantReferenceValidator referenceValidator;
    
    @Override
    @Transactional
    public Case createCase(CreateCaseRequest request) {
        Case entity = new Case();
        entity.setOwnerMemberId(request.getOwnerMemberId());
        entity.setOwnerOrgId(request.getOwnerOrgId());
        entity.setCreatedBy(TenantContext.getCurrentMemberId());
        
        // 校验引用一致性
        referenceValidator.validateOwnership(entity);
        
        return caseRepository.save(entity);
    }
}
```

**异常定义**：
```java
public class CrossTenantReferenceException extends RuntimeException {
    // HTTP 400 BAD_REQUEST
    // Error Code: CROSS_TENANT_REFERENCE
}
```

**验收标准**：
- [ ] TenantReferenceValidator 实现
- [ ] Service 层创建/更新时调用校验
- [ ] 跨租户引用返回 400 CROSS_TENANT_REFERENCE
- [ ] 单元测试覆盖跨租户引用场景

### Feature 4: SQL 多租户安全检查（Tenant SQL Guard）

**目标**：防止开发人员写出跨租户查询

**问题示例**：
```sql
-- ❌ 危险：没有 tenant_id 条件
SELECT * FROM biz_case;

-- ✅ 正确
SELECT * FROM biz_case WHERE tenant_id = ?;
```

**技术规格**：

**方案 A：MyBatis 拦截器运行时检查**
```java
@Intercepts({
    @Signature(type = Executor.class, method = "query", args = {...})
})
public class TenantSqlGuardInterceptor implements Interceptor {
    
    @Override
    public Object intercept(Invocation invocation) {
        String sql = getSql(invocation);
        if (isTenantTable(sql) && !hasTenantFilter(sql)) {
            throw new TenantSqlViolationException(
                "Missing tenant filter: " + sql
            );
        }
        return invocation.proceed();
    }
}
```

**方案 B：CI 静态检查（ArchUnit）**
```java
@ArchTest
static final ArchRule tenant_tables_must_have_tenant_filter =
    classes()
        .that().haveNameMatching(".*Mapper")
        .should(/* 检查 SQL 包含 tenant_id */);
```

**验收标准**：
- [ ] 实现至少一种检查方案
- [ ] 缺少 tenant_id 条件时报错或 CI 失败
- [ ] 白名单机制（sys_tenant 等表不检查）

# Brix 多租户开发规范

## 红线规则（必须遵守）

### Rule 1: 所有业务表必须包含 tenant_id
- 表名以 `biz_` 开头的表必须有 `tenant_id` 字段
- 必须建立 `tenant_id` 索引

### Rule 2: 所有查询必须包含租户过滤
- 禁止写不带 tenant_id 的查询
- MyBatis 拦截器会自动检查

### Rule 3: 跨租户访问必须显式标注
- 使用 @CrossTenantAccess 注解
- 必须在代码评审中说明理由

### Rule 4: 审计日志必须包含关键字段
- tenant_id
- user_id
- action
- resource_type
- resource_id

## 示例代码

### 正确写法
```java
// ✅ 查询会自动添加 tenant_id 条件
List<Case> cases = caseRepository.findByStatus("OPEN");
```

### 错误写法
```java
// ❌ 原生 SQL 必须手动添加 tenant_id
@Query("SELECT * FROM biz_case WHERE status = ?")  // 缺少 tenant_id
List<Case> findByStatus(String status);
```

### 跨租户访问
```java
// ✅ 显式标注跨租户访问
@CrossTenantAccess(reason = "平台报表统计")
public List<TenantStats> getAllTenantStats() {
    return tenantStatsRepository.findAll();
}
```

## 数据库完整 DDL

```sql
-- ============================================
-- 系统表（无 tenant_id）
-- ============================================

-- 租户表
CREATE TABLE sys_tenant (
    id BIGINT PRIMARY KEY,
    code VARCHAR(50) NOT NULL,
    name VARCHAR(200) NOT NULL,
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP,
    UNIQUE KEY uk_code (code)
);

-- 身份表（全局唯一）
CREATE TABLE sys_identity (
    id BIGINT PRIMARY KEY,
    phone VARCHAR(20),
    email VARCHAR(200),
    password_hash VARCHAR(200),
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP,
    UNIQUE KEY uk_phone (phone),
    UNIQUE KEY uk_email (email)
);

-- 租户成员关系表
CREATE TABLE sys_tenant_member (
    id BIGINT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    identity_id BIGINT NOT NULL,
    member_type VARCHAR(30) NOT NULL,    -- OWNER / ADMIN / MEMBER / CUSTOMER
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP,
    UNIQUE KEY uk_tenant_identity (tenant_id, identity_id),
    INDEX idx_identity (identity_id)
);

-- 平台管理员表
CREATE TABLE sys_platform_admin (
    id BIGINT PRIMARY KEY,
    identity_id BIGINT NOT NULL,
    role VARCHAR(30) NOT NULL,           -- SUPER_ADMIN / PLATFORM_ADMIN
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP,
    UNIQUE KEY uk_identity (identity_id)
);

-- 组织表（tenant 级别）
CREATE TABLE sys_organization (
    id BIGINT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    parent_id BIGINT,
    name VARCHAR(200) NOT NULL,
    code VARCHAR(50),
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP,
    INDEX idx_tenant (tenant_id),
    INDEX idx_parent (parent_id)
);

-- ============================================
-- 业务表模板（有 tenant_id + ownership）
-- ============================================

-- 审计日志表
CREATE TABLE biz_audit_log (
    id BIGINT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    action VARCHAR(50) NOT NULL,
    resource_type VARCHAR(100),
    resource_id BIGINT,
    changes JSON,
    ip VARCHAR(50),
    user_agent VARCHAR(500),
    created_at TIMESTAMP DEFAULT NOW(),
    INDEX idx_tenant_time (tenant_id, created_at),
    INDEX idx_user (user_id),
    INDEX idx_resource (resource_type, resource_id)
);
